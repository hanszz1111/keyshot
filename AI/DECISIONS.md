## 一、地基级决策（选型，推翻成本极高）

### ADR-001 · 形状必须由 ControlNet 或深度模型锁定

- **决策**：产品形状由结构条件（depth / normal / canny）锁定，**不靠提示词，也不靠语义图像模型**。
- **理由**：纯提示词无法保证几何一致；公共图像 API（Seedream / Nano Banana / GPT Image /
  Kontext / Qwen-Image-Edit / 混元）**都不接受 depth/normal 输入**，只能做质感 pass，不能做主 pass。
- **代价**：必须自建 Blender 出 pass 的链路，依赖本地 GPU。
- **可否推翻**：**否**。这是实测结论，且有明确的技术原因（API 不接受结构图）。

### ADR-002 · 丝印 / LOGO / 刻度 / 认证标识 / 透明件禁止 AI 生成

- **决策**：这些元素必须走引擎真渲染 + 图层回贴，**不允许交给 AI**。
- **理由**：
  1. 实测 AI 会**臆造**不存在的标牌文字。本轮修复实验中，即便加了 Canny 锁形，
     在控制强度偏低时 AI 仍往机身写了 "FIVUT" / "Mary Lihao Dosone" 之类的假标识。
  2. 认证标识（CE / FCC / RoHS）写错是**合规风险**，不只是美观问题。
  3. 刻度与量程写错会误导用户，可能造成**安全与法律问题**。
- **代价**：需要维护一套确定性渲染 + 图层合成的通道，无法全自动。
- **可否推翻**：**否**。这是底线。

### ADR-008 · 许可为第一过滤条件

- **决策**：商用场景只选 **MIT / Apache** 许可的组件。
- **已知许可状态**：

  | 组件 | 许可 | 判断 |
  |---|---|---|
  | ComfyUI 本体 | GPL-3.0 | 本地工具，可接受；不可作为云端服务对外分发 |
  | `runpod-workers/worker-comfyui` | **AGPL-3.0** | 商用有风险 |
  | `FLUX.1 Canny [dev]` | 非商用 | ❌ 排除 |
  | `FLUX.1 Depth [dev]` | 可商用 | ✅ 可考虑 |
  | IPAdapter 权重 | apache-2.0 | ✅ |
  | CLIP-ViT-H-14 | apache-2.0 | ✅ |

- **可否推翻**：**否**（除非确认了新的许可条款）。

### ADR-015 · 产品本体像素走真渲染，AI 只出背景与氛围

- **决策**：不指望 AI 生成产品本体，产品主体用真渲染，AI 负责环境、光照、氛围。
- **理由**：见 ADR-002 与「depth+normal 锁不住表面细节」的实测结论。
- **代价**：管线变长（真渲染 + AI 合成两步）。
- **可否推翻**：**是**。如果你认为存在能保住表面细节的技术路线（例如更高的控制强度组合、
  分层生成、或专门的工业产品微调模型），欢迎提出并说明验证方法。

## 二、链路级决策

### ADR-003 · 无显卡场景的最优解是托管 ComfyUI，而非图像 API

- **决策**：若无本地 GPU，优先考虑租用托管的 ComfyUI 实例，**而不是**改用公共图像 API。
- **理由**（成本与能力对比）：
  - 托管 ComfyUI（L40S）：约 **¥0.12 / 张**
  - 公共图像 API：**¥0.28–0.43 / 张**
  - 能力上，托管 ComfyUI 与本地**等价**（同样支持 ControlNet），而图像 API 不支持结构输入。
- **可否推翻**：**是**。如果你有更新的价格数据或发现托管方案有隐藏成本（如冷启动、带宽、
  模型上传限制），请指出。

### ADR-005 · 参考图强度必须显式选择，不许默认糊弄

- **决策**：接参考图时必须显式选择借用层级：`L1 风格` / `L2 材质` / `L3 整体`。
- **理由**：参考图只应借用视觉特征（配色/材质/光照/构图），**绝不替换源白模形状**。
  不显式选择会让模型自行决定，容易把源产品的形状也带跑。
- **可否推翻**：**是**。

### ADR-011 / 012 / 013 · 云端 API 相关

- **状态**：仅研究方案，**未接入**。当前网页控制台里没有任何云端提供方可用。
- **接入前必须验证**：结构图输入能力、费用、隐私（产品图外传是否可接受）、许可、失败重试。
- **可否推翻**：不适用（尚未决策）。

## 三、工程规范级决策

### ADR-004 · 8 GB 显存优先走本机低显存路线

- **决策**：在 8 GB 显存约束下，用 SDXL + Lightning 快速版（8 步）跑本机，
  不引入更大模型，除非质量/费用/许可三项都验证通过。
- **理由**：实测 SDXL Lightning 8 步在 8 GB 上可跑（~18 s/张，显存峰值约 5.8 GB）。
  更大模型（FLUX 等）在 8 GB 上跑不了，或需要量化牺牲质量。
- **可否推翻**：**是**（如果质量确实不够用）。

### ADR-006 · 只新增，不删除不改名

- **决策**：所有清理操作一律走「隔离」——移动到 `_隔离区/<日期戳>/` 并生成清单，可回滚。
- **理由**：用户明确要求「工作时不要更改源文件位置或者内容」；历史版本有追溯价值。
- **可否推翻**：**否**（用户硬性要求）。

### ADR-007 · 一个网页入口

- **决策**：运行界面只维护 `web/`，「形照」工作台。旧 UI、旧控制台作为历史归档，不再分叉。
- **理由**：曾出现两套 UI 并行导致改动落到错误分支的问题。
- **可否推翻**：**否**。

### ADR-009 · 图片改图必须自带形状约束（v2.4 新增）

- **决策**：当前 img2img 工作流**固定**接入「原图自身提 Canny 边缘 → ControlNet」作为结构条件；是否稳定保形仍待验证。
  `denoise` 区间 0.55–0.95（默认 0.85），低于 0.55 直接拒绝。
  前端滑块范围必须与服务端校验一致。
- **理由**：Windows 端单样本扫描中，裸 img2img 的 d0.50 与源图近似（全图 MAE 4.55），d0.75 则臆造了不同产品；加入结构条件值得继续比较，但尚无跨产品保形结论。
- **代价**：每张图多一次 Canny 计算（可忽略）与一个 ControlNet 前向（约 +8 s）。
- **可否推翻**：**是**。如果你认为有其他方法能在保形的同时彻底换材质（例如 tile 重绘、
  分层 latent 混合、或专门的材质迁移模型），请提出。

### ADR-010 · 模式标记缺失即拒绝（v2.4 新增）

- **决策**：任务带 `source_img` 却没有模式标记时，服务端**显式报错**，不静默降级。
- **理由**：曾因标记丢失静默走了纯文生图，**产出一张与产品毫无关系的人像**，
  而界面没有任何提示。静默降级比报错危险得多。
- **可否推翻**：**否**。

### ADR-014 · 机位角度由 `--view` 决定（v2.4 新增）

- **决策**：Blender 出 pass 脚本内建「机位 → (方位角, 仰角)」查表；
  调用方只传 `--view` 也必须得到不同取景。
- **理由**：曾因参数默认值写死 `(0,12)` 且调用方不传角度，导致**五个机位取景完全相同**。
- **可否推翻**：**否**。

## 四、明确「未决策 / 待定」的事项

这些是本项目**还没有想清楚**的地方，欢迎提出意见：

| 事项 | 现状 | 卡在哪 |
|---|---|---|
| IoU 形准指标口径 | 当前口径有系统性偏差（把 AI 背景算作前景） | 需要一个不受背景影响的同口径掩膜算法 |
| 长批次后台队列 | 未实现，浏览器关闭后不保证跑完 | 需要后端持久队列 + 取消/重试/恢复 |
| 人工质检的量化标准 | 只有「一眼辨认为同一产品」这样的主观描述 | 需要可执行的质检清单 |
| 真渲染 + AI 合成的具体分工界面 | 只有方向（ADR-015），无实现 | 需要定义合成边界与格式 |
| 2000 个 PSD 的批量改造路径 | 未规划 | 需要先跑通单图，再考虑量产 |

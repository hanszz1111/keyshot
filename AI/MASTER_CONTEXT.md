## 0. 一句话说明这是什么项目

把**产品白模/灰模**（无材质的三维模型截图）自动转成**电商主图/详情页可用的写实渲染图**。
类目：激光水平仪、气体检测仪、激光测距仪等测量仪器。存量约 2000 个详情页 PSD（中英文双版本），
现有管线是 KeyShot 渲染 + PSD 排版，本项目要用 AI 替代/加速其中「出主图」这一环。

**最终用途判断的硬边界**：出图结果**不是**最终交付物，而是**候选图**，必须经人工质检。
丝印、LOGO、刻度、量程、认证标识、透明件**不允许**由 AI 生成（见 §5 ADR-002）。

## 2. 系统架构

### 2.1 两条处理主线

```
[主线 A · 3D 白模]
  3D 源文件 (.stl/.blend/.glb/.fbx)
    → Blender 无界面渲染结构 pass (clay/depth/normal/alpha)
    → ComfyUI: SDXL + ControlNet(depth+normal) 锁几何
    → 候选图 → 人工质检

[主线 B · 现有产品图]
  产品照片 / 已有渲染图
    → ComfyUI: SDXL img2img + Canny ControlNet 锁形状
    → 候选图 → 对照原图人工质检
```

### 2.2 五层架构

| 层 | 内容 |
|---|---|
| L0 资产 | `assets/白模/`（3D 源文件）、`assets/source/`（图片改图源图）、`assets/refs/`（参考图） |
| L1 输入 | 参数卡（SKU/机位/描述/强度）；白模、源图、参考图 |
| L2 结构 pass | Blender 出的 depth / normal / alpha —— **形状的唯一来源** |
| L3 生成 | ComfyUI SDXL：ControlNet 锁形 + IPAdapter 参考 + KSampler 采样 |
| L4 后处理 | 候选图落盘、对照拼图、IoU 辅助检查 |
| L5 交付 | `outputs/<SKU>/<机位>/` + 人工质检 |

### 2.3 技术栈与运行环境

| 项 | 值 |
|---|---|
| 平台 | Windows，账号 Administrator |
| GPU | NVIDIA RTX 4060 Ti，**显存 8 GB**（这是所有选型的硬约束） |
| 出图引擎 | ComfyUI **0.37.0** 便携版，`127.0.0.1:8188` |
| 3D 引擎 | Blender **4.5.0**（无界面模式） |
| 底模 | `RealVisXL_V5.0_Lightning_fp16`（8 步快速版，首选）＋ `sd_xl_base_1.0`（对照） |
| ControlNet | `controlnet-union-sdxl-1.0-promax`（一个模型支持多种条件类型） |
| 参考图 | IPAdapter-Plus SDXL |
| 网页控制台 | 「形照」工作台，`127.0.0.1:8765`，Python 标准库实现（零第三方依赖） |
| 服务持久化 | Windows 计划任务 `AIRender_Web` / `AIRender_ComfyUI` |

### 2.4 实测性能基线

| 场景 | 耗时 |
|---|---|
| 单张白模出图（结构约束，双 ControlNet） | **18–33 秒** |
| 四机位批量（4 张） | **4/4 成功，合计 72.8 秒** |
| 图片改图（img2img + Canny） | **约 28 秒**，显存峰值 ~5.8 GB（8 GB 未 OOM） |

## 4. 关键实测数据

### 4.1 白模出图（主线 A）

四机位批量，全部成功：

| 机位 | 耗时 | 产物 |
|---|---|---|
| front | 18.2 s | `outputs/GF/front/ai_render_00015_.png` |
| 3q4_left | 18.2 s | `outputs/GF/3q4_left/ai_render_00016_.png` |
| 3q4_right | 18.2 s | `outputs/GF/3q4_right/ai_render_00017_.png` |
| side | 18.1 s | `outputs/GF/side/ai_render_00018_.png` |

### 4.2 ★ 最重要的技术结论

> **depth + normal 锁得住「轮廓与大体块」，锁不住「表面细节」。**
> AI 会**臆造 CAD 里根本不存在的表面特征**（格栅、孔点、罗纹）。
> **拉满控制强度（1.0/0.9）反而更差**（画面被裁切、臆造依旧）。

→ 因此**产品本体像素必须走真渲染**，AI 只负责背景与氛围（ADR-015）。

### 4.3 形准 IoU 指标：未达标，且指标本身有缺陷

实测四机位 IoU：front 0.249 / 3q4_left 0.316 / 3q4_right 0.374 / side 0.382，**平均 0.330**（门槛 0.90）。

**但这个数字不能直接当结论用**，原因是：

1. 白模背景近黑（灰度均值 16.9），AI 成图是影棚亮背景（均值 126.4）；
2. 成图侧剪影用「四角底色扣除」算法求，会把 **AI 新增的背景**算作前景；
3. → 剪影面积可能虚高、IoU 可能被压低；同时**不能排除成图真实变形或构图变化**。

**互验**：浏览器端与独立 Python 端复算 front 机位结果完全一致（均 0.249），只说明两端按现有算法计算一致，
**不能证明前景掩膜或产品形准正确**。此点已在文档中标记为「P1 待修正：IoU 口径需改为同口径主体掩膜比较」。

### 4.4 图片改图（主线 B）—— 本轮的修复重点

**修复前的问题**（用户报告「图生图基本没有渲染」）：

| 配置 | 与源图平均像素差 | 表现 |
|---|---|---|
| 8 步 / denoise 0.50（旧默认） | **4.55 / 255** | 等于原样返回，**完全没渲染** |
| 8 步 / denoise 0.75 | 43.60 | 有渲染，但**臆造出一把雷达枪**（完全换了产品） |
| 30 步 / denoise 0.70 | 22.18 | 有渲染，但臆造水印 "Stuiio Product Deⅵer" |

**该样本中的解释**：Lightning 8 步底模在 `denoise 0.50` 下有效采样步数少，输出近似原图；
裸 img2img 缺少显式结构条件，提高 denoise 后该样本出现了明显跑形。**这不证明所有产品或所有参数都必然二选一。**

**当前候选方案**：用原图自身提取 Canny 边缘，送 ControlNet 提供结构约束；高 denoise 下的材质变化与保形稳定性仍须跨样本验证。

**对照实验结果**：

| 配置 | 平均像素差 | 结论 |
|---|---|---|
| N1 无 ControlNet / d0.85 | 56.58 | ❌ 形状全丢，臆造 "GRONAL" 标牌 + 水印 |
| **C1 ControlNet 0.75 / d0.85** | **74.80** | 该样本候选配置；全图 MAE 不证明主体换材或保形 |
| C2 ControlNet 1.00 / d0.85 | 65.22 | 偏保守，改动略不足 |
| C3 ControlNet 0.75 / d0.70 | 41.55 | 改动不足 |

**Windows 执行方报告的接口验证**：脚本经 `/api/tasks → /api/comfy/submit → /api/comfy/poll`，`mode=img2img`，13 节点含 ControlNet 链，约 28 秒产出
`outputs/stl_2/photo/ai_render_00027_.png`。该脚本**不是网页使用的受控提交入口**；执行方观察到窗口、格栅等边界较接近且该图无臆造 LOGO，但对照图未入公开仓库，Mac 无法独立确认。见 [R1 复审](REVIEW.md)。

### 4.5 Blender 机位角度（本轮另一修复）

**问题**：调用方只传 `--view`，而脚本 `--azimuth/--elevation` 默认值写死 `(0, 12)`
→ **五个机位全部用同一组角度取景**，「正面」实际渲染成端面/俯视视图。

**修复**：脚本内建机位→角度查表（front `(0,8)` / 3q4_left `(-45,15)` / 3q4_right `(45,15)` /
side `(90,8)` / top `(0,80)` / detail_keypad `(-30,35)` / detail_window `(30,30)`），
参数默认改为「未指定时按机位查表」。

## 7. 已知的坑（供你判断我的建议是否可靠）

这些是我实际踩过的，列出来是为了让你知道哪些地方我容易出错：

1. **指标容易被背景变化污染**（§4.3）—— 我一度差点把 IoU 0.330 当成界面 bug。
2. **前后端参数范围曾不一致** —— 前端滑块允许 35%，后端拒绝 <55%，用户会被莫名拦下。
3. **任务模式标记缺失会静默降级** —— 曾因标记丢失走了纯文生图，产出一张人像，
   而界面没有任何提示。现已改为显式报错。
4. **服务进程会被回收** —— agent 起的进程随对话结束消失，必须用计划任务承载。
5. **PowerShell 5.1 的 BOM 问题** —— `.ps1` 不带 UTF-8 BOM 会把中文按 ANSI 解析成乱码。
6. **`grid` 容器里的 `height: 100%` 不可靠**（R2）—— `.hero` 是 `display:grid`，
   grid area 高度不确定时百分比高度**会失效**并回退成「按图片固有比例算高度」，
   图就比容器高、被 `overflow:hidden` 裁掉。用户看到的是「白模只有一半」。
   → 要让子元素严格贴合容器，用 `position:absolute; inset:0`。
7. **3D 变换矩阵是 `T(position)·S(scale)`**（R2）—— 顶点**先缩放再平移**。
   拿未缩放的世界坐标当 `position` 会把模型推出画面（canvas 一片空白）。
   → 放进 `Group`，`root.position` 用 Group 局部坐标。
8. **插件「启用了」不等于「可用」**（R2）—— `addon_utils.enable()` 在 `--background` 下
   会抛 KeyError，但类**已经注册**（`hasattr(bpy.ops...)` 为真），只是 Scene 上的
   PointerProperty 没挂上；`read_factory_settings()` 则会把已启用插件**一起卸载**。
   → 判据要用 `hasattr(bpy.context.scene, "<prop>")`，且清场不要用 `read_factory_settings`。
9. **静态资源没设 `Cache-Control` 会出现「改了没生效」**（R2）——
   浏览器启发式缓存会不询问就直接复用旧 JS。用户看到的还是旧界面，
   于是「明明修了却还是老样子」。静态资源要补 `no-cache, must-revalidate`。
10. **持久化服务会让「改完代码的测试」假通过**（R2）—— 旧服务一直占着端口，
    新进程绑定失败静默退出（症状是**新服务日志 0 字节**），请求全打给旧代码。
    → 测试用备用端口，并**每次改动留一个「旧代码不可能有」的可观测标志**
    （新字段/新文案），测试第一步就查它。改完必须重启服务才生效。

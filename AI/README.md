# AI/ · 跨机协作目录

本目录用于和**另一台电脑上的 GPT** 协作。GPT 无法访问本项目文件系统，
因此文件全部**自包含**——所有需要判断的事实都写在文本里。

## 文件说明

| 文件 | 谁写 | 是否可改 | 作用 |
|---|---|---|---|
| `MASTER_CONTEXT.md` | 本机 Agent | ❌ 只读 | 全局事实、架构、路径契约、关键数据、已知的坑 |
| `DECISIONS.md` | 本机 Agent | ❌ 只读 | 架构决策记录（ADR），含「可否推翻」标记 |
| `TASK.md` | 本机 Agent | ❌ 只读 | **本轮请 GPT 评审什么** |
| `RESULT.md` | 本机 Agent | ❌ 只读 | 执行结果与原始证据 |
| `REVIEW.md` | **GPT** | ✅ GPT 填写 | 评审意见，填完交回 |

`README.md`（本文件）说明流程与版本，通常无需修改。

## 使用流程

```
① 本机 Agent 更新 MASTER_CONTEXT / DECISIONS / RESULT，并在 TASK.md 写明本轮问题
        ↓
② 把 AI/ 目录（或 4 个文件的内容）发给另一台电脑的 GPT
        ↓
③ GPT 阅读后填写 REVIEW.md，交回
        ↓
④ 本机 Agent 按 REVIEW.md 的意见执行，并把处理结果写回 RESULT.md
        ↓
⑤ 进入下一轮（R2、R3…），TASK.md 更新为新问题
```

## 协作约定

- **GPT 是评审者，不是执行者**：只做方案与文档评审，不改代码、不跑渲染。
- **不许附和**：没找到问题就明确说「没问题」，不要为凑篇幅罗列泛泛建议。
- **结论必须有证据**：本机的每个数字都应能在 `RESULT.md` 找到出处；
  找不到就标记为「证据缺失」。
- **不接受需要访问机器的建议**：双方都无法让对方在自己的机器上执行命令。

## 注意事项

- 本目录是**协作材料**，不是项目的权威文档。项目权威文档仍是根目录的
  `00-AI白模渲染器-过程文档.md`（单一事实来源）。
- 若本目录内容与权威文档冲突，**以权威文档为准**，并请告知执行方修正。
- 本目录内容如涉及尚未定论的判断，会在文中显式标注（例如「我认为是方法问题，但我无法证明」），
  请勿把这类**自陈的不确定性**当作已确立的结论。

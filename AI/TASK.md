## 二、请你重点评审的三个问题

### ★ 问题 1（最高优先）：我用 Canny ControlNet 锁形状的结论可靠吗？

**我的结论**：给图片改图接入「原图自身提 Canny 边缘 → ControlNet」，就既能彻底换材质
（平均像素差 74.80）又能保住形状。

**我的证据**：
- 无 ControlNet / d0.85 → 差 56.58，形状全丢，臆造 "GRONAL" 标牌
- ControlNet 0.75 / d0.85 → 差 74.80，形状一致（**我据此判定为推荐配置**）
- ControlNet 1.00 / d0.85 → 差 65.22
- 另有端到端验证：真实接口链路产出图，肉眼确认形状保留

**请你判断**：

1. **平均像素差（MAE）是不是一个合适的「渲染是否有效」指标？**
   我意识到它有个问题：MAE 高可能来自**背景整体变亮**，而不一定是产品本体被重新渲染。
   如果源图是深色底、成图是亮背景，MAE 会天然偏高。**这个指标能支撑我的结论吗？**
2. **「形状保留」我目前靠肉眼判断**（看大窗口轮廓、分模线、格栅弧线是否还在）。
   有没有可执行、不依赖人眼的方法？注意：我试过的 IoU 指标有系统性偏差（见下）。
3. **我是否漏掉了某个失败模式？** 例如控制强度与 denoise 的交互、不同机位/材质下的稳定性。
   我只在**一张源图、一个种子**上做了对照实验 —— 这个样本量够吗？

### ★ 问题 2：我的 IoU 指标错在哪里，应该怎么改？

**现状**：四机位 IoU = 0.249 / 0.316 / 0.374 / 0.382，**平均 0.330**，门槛 0.90，**未达标**。

**我的归因**：白模背景近黑（灰度均值 16.9），成图是亮背景（126.4），
我的剪影算法「四角底色扣除」把 **AI 新增的背景算成了前景** → 剪影虚高、交集偏低。

**互验**：浏览器端与独立 Python 端复算同一机位结果完全一致（均 0.249）→ 计算没错，是方法有问题。

**请你判断**：

1. 我的归因对不对？有没有别的解释（比如模型确实改变了产品比例）？
2. 应该怎么设计一个**不受背景影响**的掩膜算法？
   我想到的方向：白模侧用 alpha 通道（但注意：本项目 alpha 通道恒为 255，
   真实掩膜在 **RGB 灰度**里，白=物体）、成图侧用「与源图的差异区域」或语义分割。请评估可行性。
3. **门槛 0.90 本身是否合理？** 这个数字是我早期定的，没有依据。对一个「AI 生成产品图」的任务，
   合理的形准门槛应该是多少？还是说 IoU 根本不适合衡量这件事？

### ★ 问题 3：我该不该继续投入这条 AI 出图路线？

**我的现状**：
- 出图能跑通（18–33 秒/张，四机位批量 4/4）
- 但形准未达标，且 AI 会**臆造 CAD 里不存在的表面特征**
- 我已确立 ADR-015：产品本体走真渲染，AI 只出背景与氛围

**请你判断**：

1. 如果 AI 只能出背景与氛围，那**这套管线的价值还成立吗**？
   换句话说：真渲染 + AI 合成，相比「真渲染 + PS 手工合成」，优势有多大？
2. 是否存在我没考虑到的技术路线，能让 AI 真正保住产品表面细节？
   （我试过拉满控制强度，结果更差；也确认过公共图像 API 不支持结构图输入）
3. 从 ROI 角度，对于一个有 2000 个 SKU 存量、有 KeyShot 真渲染能力的团队，
   应该把力气花在哪里？

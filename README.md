# 形照 · AI 白模产品渲染器

这是一套在 Windows 上运行的本地产品渲染工作台：导入自己的 3D 白模，准备结构图，描述材质、配色与灯光，再由 ComfyUI 生成候选图。当前主界面只有一套：`web/`。

## 一键启动

双击项目根目录的 **`一键启动.bat`**。它会检查已有服务，按需启动 ComfyUI 和网页控制台，然后打开正确的网页地址。旧的 `启动全部.bat` 也指向同一套启动流程；日常使用只需记住 `一键启动.bat`。

首次启动前确认：

1. Windows 上已有 ComfyUI 便携版，默认位置为 `F:\AI-Renderer\packs\ComfyUI_windows_portable`。如果安装在别处，设置系统环境变量 `AI_RENDER_COMFY_ROOT` 为该文件夹完整路径。
2. 便携版内有 `python_embeded\python.exe`。没有便携版时，网页可用已安装的 Python 3.11+ 启动，但无法调用本地出图引擎。
3. 模型、ControlNet 和参考图组件按实际工作流安装。缺少组件时，网页的服务状态和出图前检查会提示。

脚本默认使用 `--lowvram` 适配 RTX 4060 Ti 8GB。网页通常是 `http://127.0.0.1:8765/`；如果端口被其他程序占用，会选择 8765–8785 中的可用端口并自动打开它。ComfyUI 地址为 `http://127.0.0.1:8188/`。如果两个服务已运行，脚本会复用，不会重复启动。

停止时关闭本次启动的网页服务与 ComfyUI 窗口；脚本不会结束它发现并复用的已有服务。也可以双击 **`停止服务.bat`**（等价于运行 `scripts/stop_all.ps1`）一次停掉两个服务并释放端口。

**服务是持久的**：启动脚本会把两个服务注册为 Windows 计划任务（`AIRender_Web` / `AIRender_ComfyUI`）再拉起，因此它们由系统的任务计划服务持有，**关掉启动窗口后仍然继续运行**。计划任务不可用时脚本会自动退回普通进程启动，保证在任何机器上都能跑通。

### 启动遇到问题

| 现象 | 处理 |
|---|---|
| 找不到 ComfyUI | 核对便携版目录，或设置 `AI_RENDER_COMFY_ROOT`；可先使用网页整理白模，但暂不能出图。 |
| 找不到 Python | 安装 Python 3.11+，或使用带内置 Python 的 ComfyUI 便携版。 |
| 网页已打开但显示渲染服务离线 | 等 ComfyUI 完成加载，在网页点“刷新状态”；若仍离线，查看 ComfyUI 窗口报错。 |
| 网页没有自动打开 | 查看启动窗口打印的 `Web UI` 地址，复制到浏览器。 |
| 重复双击启动 | 脚本会识别同一项目的已有服务；不要手动结束其他项目的进程。 |

## 出一张图

1. 在网页“选择产品”中导入 `.blend`、`.glb`、`.gltf`、`.obj`、`.stl`、`.fbx`、`.stp`、`.step` 或 `.3dm` 白模，可直接生成结构图。
   - **`.stp/.step`**：首选 Blender 的 **STEPper** 插件（自带 OpenCASCADE 内核，**无需安装 FreeCAD**），在 Blender 首选项里启用即可；插件缺失时才回退到「先用 FreeCAD 转缓存网格」，此时需安装 FreeCAD，若网页未识别则设置 `FREECAD_CMD` 为 `FreeCADCmd.exe` 完整路径并重启服务。
   - **`.3dm`（Rhino）**：装 Blender 的 [import_3dm 扩展](https://github.com/jesterKing/import_3dm)（v0.0.18 起自带 `rhino3dm` 依赖，装完即用）。Blender 4.2+ 的命令行安装方式：`blender.exe --command extension install-file -r user_default -e import_3dm-<版本>-windows_x64.zip`。该扩展主要读取文件里的渲染网格，纯 NURBS/曲面文件可能需先在 Rhino 中生成渲染网格或导出 GLB/OBJ。
   - `.ksp/.c4d/.max` 仍需手动导出为 GLB/OBJ（KeyShot 导出 GLB，C4D/Max 导出 GLB 或 OBJ）。
   - **`.rhi` / `.rhp` / `.yak` / `.3dmbak` 不是模型文件**（分别是 Rhino 插件安装包、插件、插件包、备份文件），上传时会被明确拒绝并提示改用 `.3dm` 或导出 GLB/OBJ。
   - **上传有两道预检**：扩展名不在白名单会被拒；文件内容与扩展名不符（改过后缀、传了一半、已损坏）也会被当场拦下并说明原因，不会在投放区留下「看起来在、其实用不了」的文件。
   - 上传的原文件不会因转换被修改；仅 FreeCAD 回退路径会产生缓存，位于 `assets/_转换缓存/`。
   - **导入成功会自动生成一张白模预览图**（3/4 视角，与正式结构图共用同一相机方位与取景算法，所以预览里看得到的部位，正式机位一定也在画面内）。预览由 Blender 在后台生成，通常十几秒内出现在「选择产品」下方；换了模型会自动重出。缓存位于 `assets/_缩略图/`。
2. 在“任务”中为目标视角生成或上传深度图。结构约束模式缺少深度图时会阻止出图，不会悄悄降级为纯文字生成。
3. 写下材质、配色、灯光和细节要求；可上传参考图。界面会说明参考图当前是作为图像条件参与生成，还是只提取颜色和影调。
4. 在“出图视角”里**任意勾选**要出的机位（六视图 + 3/4 视角 + 两个特写，共 10 个），或用快捷按钮「仅预览视角 / 4 标准 / 全选 / 清空」；再选每个视角的候选张数（1/2/4/15/30/50）。**总张数 = 勾选视角数 × 每视角张数**，按钮上会实时显示。若某个机位还没有深度图，预检会列出来并暂时禁用按钮——先在「任务」里给那个机位生成结构图。
5. **出图尺寸**默认「跟随结构图」，即采用该机位结构图的**实际像素尺寸**。
   - ⚠️ **不要把它改成与结构图不同的宽高比** —— 那会把产品拉变形。（旧版本固定用 1024×1024、而结构图是 1232×752，宽高比从 1.64 压成 1.0，产品被明显拉长。）
   - 也可选预设或自定义（填「宽 x 高」，会自动对齐到 8 的倍数）。
6. **渲染质量**四档：草稿 8 步 / 标准 12 步 / 精细 20 步 / 最高 32 步。
   - 默认底模是 Lightning **蒸馏**模型，**步数超过约 20 后收益递减**，堆太高反而可能过饱和。
   - **想要更清晰，优先把尺寸调大**，比堆步数有效得多。
7. 检查提示后开始生成。全部机位各选 50 张会创建很多任务，逐张执行，需保持网页与渲染服务运行；中断后可在任务列表续跑。结果保存在 `outputs/<产品编号>/<视角>/`。

### 用对比滑杆自查形准

预览区有五个档位：**白模 / 3D 自由旋转 / 深度 / 成图 / 对比**。
- **3D 自由旋转**：在浏览器里直接转动白模看各个面（拖动旋转、滚轮缩放、双击复位）。它加载的是后端从模型导出的 GLB，不是原始 `.stp/.3dm`，所以网页端不会因为 CAD 解析出问题而卡住。首次生成需要十几秒（与缩略图一起在后台跑），生成后即点即用。
  - 底部有一条视角快捷栏：**前 / 后 / 左 / 右 / 上 / 下**（六视图）、**等轴**、**复位**、**自动转**，右侧实时显示**方位角与仰角**。
  - 这些角度与结构图机位是**同一套**（前=0°/8°、右=90°/8°、上=0°/80°…），所以在 3D 里相中的角度，出结构图时就是同一个角度。
  - **点选部件**：单击任一部件会高亮它，左上角显示「名字 / 部件编号 / 三角面数 / 全模型部件总数」；点空白处或按「取消」还原。部件编号与结构图产物 `objectid.png` 的颜色编号一致，后续可用于按部位指定材质。
    - 部件名来自**源文件本身**：Rhino 导出的 `.3dm` 常全是「物体.001」，STEP 往往带编号（如 `102990008`、`A1_99_1_1`）。名字不直观是数据的问题，**以高亮为准来认部件**。
- **白模**：Blender 渲染的该机位结构图。若发现画面被裁切或留白异常，刷新即可（预览图已改为绝对定位适配容器）。
切到“对比”后，画面左半是白模、右半是最新成图，拖动滑杆或用 `←` `→`（按 `Shift` 加快 5 倍，`Home` / `End` 到两端）即可来回比对轮廓是否偏移。结果卡上的“对比白模”按钮也能直达该档位。

两点边界要知道：

- 白模和成图的宽高比不一致时，界面会**自动改成左右并排**并提示不能按像素重合判断，不会强行拉伸对齐。
- “产品图片”模式没有白模，因此不提供该档位。
- 它只是**同视角自查工具**，不是形准结论；孔位、丝印、刻度、透明件仍须人工逐张核对。

### 直接用图片出图

1. 第 1 步切换到“产品图片”，上传一张 PNG、JPG 或 WEBP 产品照片/现有渲染图（不超过 20 MB；按最长边缩到 1024 像素后，短边须至少 256 像素）。源图保存在 `assets/source/<产品编号>/`，再次上传不会覆盖旧图；默认使用该产品最新一张。
2. 第 2 步描述希望改变的材质、配色、灯光或场景。可另外上传“参考图”借鉴风格；不要把产品原图误放进参考图入口。
3. 第 3 步调整“改动幅度”（默认 **85%**，范围 55%–95%），选择候选张数后开始生成。结果保存在 `outputs/<产品编号>/photo/`。这一模式不需要白模或深度图，也不会自动生成其他视角。
   - **白模/灰模截图**会被自动识别，提示词随之改写为「把它变成有材质的成品」。这种输入建议直接用默认 85%。
   - 低于 55% 会被服务端拒绝 —— 在 8–12 步的 Lightning 底模下，有效步数不足，出图会等于原样返回。

图片改图使用 ComfyUI 的 SDXL img2img 工作流，图片本身通过 VAE 编码进入采样器，同时由原图提取 Canny 边缘送 ControlNet 作结构约束。**85% 是当前默认改动幅度，不是保形保证**：Windows 端已在一个样本上出图，跨产品、机位和随机种子的稳定性尚未验证；文字、标识、孔位与细小结构仍须人工核对。当前界面未接入云端 API。

注意：AI 可能改动孔位、丝印、刻度、LOGO 和透明件。正式交付前应对照白模与原始标识检查；这些关键细节优先用确定性渲染与后期回贴。

## 文件放在哪里

| 位置 | 用途 |
|---|---|
| `web/` | 唯一运行中的网页界面与本地服务。`index.v17.html` / `index.classic.html` 是旧版归档，不参与运行。 |
| `assets/白模/` | 导入的 3D 文件。 |
| `assets/passes/` | 各产品、各视角的白模图、深度图和法线图。 |
| `assets/refs/` | 参考图。 |
| `assets/source/` | 图片改图的产品源图，按产品编号保存。 |
| `outputs/` | 生成图和质量记录。 |
| `config/` | 工作流、默认参数与任务数据库。 |
| `00-AI白模渲染器-过程文档.md` | 当前方案、风险、待办与后续修改登记。 |
| `docs/archive/` | 旧版详细方案和被精简的历史文档；只作追溯，不作为当前操作指令。 |

## 当前边界

- **Windows 端已有实测记录**（2026-09-27，RTX 4060 Ti 8GB / ComfyUI 0.37.0）：白模出图单张约 18–33 秒；四机位批量 4/4 成功、合计 72.8 秒；早期图片改图单张 12.1 秒、显存峰值约 5.8 GB，v2.4 加入 Canny 后另有单张约 28 秒的记录。两次速度来自不同链路，不应混作同一性能基线。
- **形准尚未通过可靠量化验收**：当前 IoU 算法得出四机位平均 0.330，低于早期暂定的 0.90；背景扣除存在明确缺陷，但也不能据此排除真实形变。0.90 尚未用人工接受样本标定，修正掩膜和复核关键结构前，不把该数值单独用作通过或失败结论。
- **AI 会臆造 CAD 里没有的特征**：本轮四机位成图可见凭空出现的格栅、孔点与罗纹。产品本体像素建议走真实渲染，AI 只出背景与氛围；丝印、LOGO、量程、认证标识、刻度、透明件必须确定性渲染 + 图层回贴。
- 网页目前顺序提交与轮询任务。浏览器关闭后可在任务抽屉继续处理待办，长期批量任务尚需后端持久调度。
- 云端图像 API 或中转服务尚未成为此网页的可用出图入口，不要把方案文档里的备选路线误认为已接入功能。

当前设计、验证状态和每次修改见[过程文档](00-AI白模渲染器-过程文档.md)。

# GitHub 调研：精确材质控制与产品多视角一致性升级大纲

> 2026-09-29 调研与设计提案。本文不表示功能已经安装、集成或经 Windows 4060 Ti 8GB 验收。目标是让同一产品的前壳、握持区、按键等部位在八个视角中保持相同的几何、材质分区、纹理方向和 CMF 方案；AI 只在可控范围内提升画面表现。

## 一、结论先行

**最可靠主线：同一份 3D 资产 → 稳定部件 ID / 材质 ID → 一套 CMF 方案 → 固定八机位与统一灯光 → 确定性渲染主体 → AI 只处理背景/光效或明确掩膜内的局部。**这比“八张图片分别让模型猜同一产品”更接近精确控制。现有千问双图与 SDXL 深度控制可继续作为审美候选，但都不能保证像素级材质边界或隐藏面的真实结构。

项目现在已有部件拾取、CMF 预设、按机位保存单部件分配、对象 ID 掩膜、局部重绘和八面候选系列；缺口是整机任务仍主要用一个主体材质提示词，已保存的部件分配没有统一作用于八个视角的最终渲染输入。详见[多部位材质组合大纲](多部位材质组合与选区渲染-实施大纲.md)。

## 三、推荐系统结构

```text
CAD / GLB / 3DM
  → 规范化部件与稳定几何指纹
  → 用户确认语义分组：前壳、握持包胶、按键……
  → 单一 CMF 方案：材料 ID、颜色、纹理尺度/方向、工艺
  → 单一场景八机位：固定相机、灯光、曝光与色彩管理
  → 同步输出：彩色主体 + 深度 + 法线 + 对象 ID + 材料 ID + alpha
  → 可选 AI：只在背景或批准的部件掩膜内处理
  → 逐机位质检 → 同系列结果板
```

### 3.1 锁定产品身份：先锁数据，再锁提示词

- 一个产品系列使用同一 `model_fingerprint`、`part_map_version`、`cmf_scheme_id/version`、灯光方案版本和相机表；任务表保存这些版本，任何一个变化都创建新系列，不在旧系列中混入结果。
- “前壳”“握持区”作为跨机位**3D 语义分组**保存；当前视角的对象 ID 只是它在该视角的投影。模型重导入时按稳定源路径/名称、几何拓扑和人工确认重新映射，绝不只复用数字 `partId`。
- 若前壳与握持区在 CAD 中是同一连续网格，系统必须提示“需划分面组/选区”，不能假装点击一个对象就能精确分出两种材料。2D 画笔只能修当前视角，不自动生成背面材质边界。

### 3.2 锁定材质：几何赋材优先，AI 只做可回退的美化

- 全局方案存每组 `material_id`、颜色、粗糙度、金属度、贴图文件 hash、纹理毫米尺度/方向、工艺说明和覆盖顺序；不同机位读取同一值。前壳 ABS 与握持 TPE 的分界由几何/材料 ID 决定，而非每张图片各写一遍文字。
- 在 Blender 中从同一模型与方案生成八个视角的真材质主体底图。预览可降采样，正式图复用同一 shader、贴图及色彩管理配置；光照改变亮度，不改变材料身份。透明件、标识与刻度走确定性渲染/回贴。
- AI 若修改主体，只允许在审核过的材料掩膜中；产物用现有 ROI/合成链路贴回，掩膜外像素必须与底图一致。对 AI 难以稳定处理的材质边界，退回真渲染结果，不靠堆提示词“修到看起来差不多”。

### 3.3 锁定八视图：一次方案，多相机渲染

- 同一场景内定义八个相机位姿和共同焦距/正交策略；每机位同步生成彩色、深度、法线、对象 ID、材料 ID，文件都带 `scene_hash + camera_id + pass_version`。三维结构先决于 AI 出图。
- 跨视角检查**语义归属**，不是直接比较 RGB：橡胶在不同光照/角度下像素本来就会不同。用材料 ID 掩膜核对“握持区始终是 TPE”；用无光照/中性光材质样本检查配色，用真实渲染图检查反射和设计美感。
- 千问若作为实验增强：目标机位的彩色材质底图是主参考，主视图只提供身份辅助；提示词明确不复制主视图相机。由于当前千问链路没有等价的硬材料 ID 约束，结果必须逐张过分区质检；未过者保留真渲染主体。

## 四、实施顺序（不重装现有千问）

| 阶段 | 具体改动 | 可交付的验收证据 |
|---|---|---|
| P0 · 基线与资产审计 | 选一件真实产品，确认前壳/包胶是否为独立网格；冻结模型、八机位、现有材质包样本。给当前八面图建立“部件归属、颜色、孔位、纹理方向、结构形准”逐张检查表。 | 资产类型、部件映射表、当前失败图和参数留档；私人模型不上传公开仓库。 |
| P1 · 稳定部件 + CMF 方案 | 在现有 `/api/partcmf` 基础上增加 3D 语义分组与版本化整套方案；前端可选前壳 ABS、握持区 TPE 并保存 A/B；旧任务只读兼容。 | 重开网页和切换八机位仍指向同一物理部位；模型变更触发重映射，不静默串材。 |
| P2 · 同场景多通道真渲染 | 扩展现有 Blender 脚本，输出八机位的材质底图、材料 ID、对象 ID、深度与法线；先用已有材质预设的纯色/PBR 基线，再接用户材质包。 | 八机位 RGB 与 ID 同相机对齐；前壳/握持分界正确；同方案重复渲染结果可复现。 |
| P3 · 精准选区与 AI 增强 | 以 P2 底图为基础调用现有 ROI/合成；千问只作可选增强，SDXL 保留局部路线。拒绝空掩膜、过期结构图、跨机位掩膜；保留真渲染原图可一键回退。 | 未选区逐像素不变；相邻塑料/包胶边界无串色；八面图身份和材料归属逐张通过。 |
| P4 · 自动质检和性能 | 自动比对 `material_id` 与预期分组、结构图轮廓、产物来源和模型/方案版本；在 Windows 4060 Ti 8GB 上测内存/显存/时长。 | 提供逐张通过/失败原因；先单张，再正侧 3/4，最后完整八面；不得只报平均美观分。 |

## 五、Windows 8GB 与风险边界

- 首轮不同时加载额外大模型、全分辨率 PBR 贴图和八张千问候选；按机位顺序处理，贴图做尺寸/格式预检并复用缓存。Blender 真渲染可先低分辨率预览，再逐张正式输出；显存峰值以 Windows 实测为准。
- 导入 STEP/3DM 可能丢失原始材料名、层级或把多部位合并；必须在 P0 看真实资产。用户若只有一张产品照片，无法据此保证隐藏面和八面物理一致。
- `KHR_materials_variants`、MaterialX、USD 是借鉴方向，不代表本轮必须加入三个依赖。优先改好现有 Blender、CMF JSON、对象 ID 和任务元数据这条最短链路。
- 许可证、素材版权和用户自己的材质包格式在真正安装/发布前再逐项确认；本文只调研公开仓库能力，不下载模型权重或上传用户素材。

## 六、成功标准

对同一个模型做至少“前壳塑料 + 握持橡胶 + 金属按键”两套配色，在八个固定机位各输出一组：部件数量/位置不漂移；材料 ID 归属与方案一致；橡胶不跑到前壳；纹理尺度与方向同物理面一致；AI 修改范围外像素不变；结果可追溯到同一模型和 CMF 版本。美感另由人工评分，不用美观度掩盖结构或材质错误。阈值需用实际样本和人工标注标定，不在方案阶段凭空宣布“保证 100% 一致”。

# Qwen-Image-2.1 工业产品精度与画质优化方案

更新：2026-10-07。对象是本项目 Windows 端 RTX 4060 Ti 8GB、Qwen-Image-2.1 INT8 + Qwen3-VL W4A8、ComfyUI 图片编辑链路。本文件是**调研和下一轮执行设计**，不是已完成的画质升级或 Windows 实图验收。

## 一、结论先行

要同时提高“精度”和“高级感”，不要把它们压给一次生成：**CAD/Blender 锁定形状和部件材质 → 千问只做受控的光照、表面微质感和背景增强 → 与原模型逐视角核对 → 不合格就保留 PBR 保形图**。千问能用多参考图辅助外观一致性，但不能把提示词或同种子当作几何硬约束。官方模型有原生 2K 能力，**不等于这台 8GB 机器能稳定运行 2K 多参考编辑**。[Qwen 官方仓库](https://github.com/QwenLM/Qwen-Image-2.1)、[ComfyUI 官方编辑模板](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_qwen_image_2_1_image_edit.json)

当前最高优先级是验证**负面提示词可能没有起作用**：仓库的 `config/render_defaults.json` 将千问 CFG 固定为 1.0，`web/app.js` 和设计预设却把大量“不添孔、不造文字、不脏背景”放入 `negative`。ComfyUI 官方模板明确说明在 CFG=1 时负面提示词不使用。不能直接推断每张坏图都由此造成，但必须停止把这些负面词视为已生效的防护。[ComfyUI 官方编辑模板中的参数说明](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_qwen_image_2_1_image_edit.json)

| 提示词增强器 | 当前未装官方 PE-I2I。 | Qwen 官方推荐专用 Qwen3.5-VL 9B 提示词改写，但其内存/显存成本对 8GB 主机显著；可考虑 API 或先生成文字、卸载增强器、再运行千问，不能默认并驻。[官方仓库](https://github.com/QwenLM/Qwen-Image-2.1/tree/main/prompt_rewrite) |

## 三、目标拆分：先保真，再美化

1. **形状精度（硬门槛）**：当前机位、外轮廓、孔位、按钮数量、分模线和部件边界与原模型一致。顶视/仰视必须真顶/真底，3/4 两侧必须可见。若白模/PBR 底图错，先修 CAD 导入或相机，不启动千问调参。
2. **CMF 一致（硬门槛）**：同名网格在八面始终同材质/色号；高光可随角度变化，材质归属不能变。PBR 底图和对象 ID 是对照基线，千问图若串区则回退底图或局部修复。
3. **视觉质量（可优化）**：金属反射受控、塑料/橡胶粗糙度可信、接触阴影自然、背景干净、主体在画面中占比稳定。画质和美感需人工盲评，不能用采样步数代替。
4. **成套一致（整组门槛）**：八张必须能被识别为同一件产品；一张漂亮、七张错色不算成功案例。

## 四、分阶段实施方案

### P0：先把现有链路测准，不增加模型

- 建立一件“金标准”CAD：有非对称孔位、清晰分模线、塑料前壳、橡胶握持、金属按钮。为每机位保存同场景 `clay/depth/normal/objectid/PBR`、相机参数与材质方案版本。缺任何输入或尺寸不一致，不进入 AI。
- 增加可导出的“任务事实卡”：源文件哈希、机位、CMF 方案版本、设计预设签名、第一/第二参考图哈希、最终 prompt、negative、CFG、步数、预算、实际输出宽高、种子、模型权重名称、ComfyUI 工作流版本、GPU 耗时和错误。不要只保存界面选项名。
- 用**同一输入、同一种子、同一参数**先比较 A=当前提示词与 B=“一句具体编辑动作 + 一句产品/几何保留 + 一句 CMF/光照目标”。在 CFG=1 下，关键禁令放入正向“只改表面/光照，保留所有未指定结构”，不依赖 `negative`。先 2 个困难机位 × 2 种子；有效再扩 8 面。不要同时改步数和分辨率。
- 单独做 CFG=1 与稍大于 1 的受控试验，仅验证负面词是否真正生效及是否带来过曝/变形/变慢；**不把 CFG 3–7 当默认建议**。若无稳定收益，保留 1。

### P1：改输入质量和局部范围，避免整图重画

- 将“真材质底图”作为高保形候选的默认**实验基线**，不是立即替换所有用户默认；确保 Blender 底图自身已达到可接受的构图、CMF 与光照。对于多材质产品，优先修对象 ID/网格映射而不是写更长提示词。
- 先做单一部件/背景的局部编辑原型：明确可编辑 mask，其他像素从 PBR 基底保留；输出后按对象 ID 边界合成并检查接缝。官方模型有局部编辑能力，但当前 ComfyUI 工作流没有 mask 输入；具体节点/API 需小样验证后实现。
- 对高品质最终图尝试“PBR 高分辨率主体 + 千问低/中分辨率局部增强 + 受控合成”。这样 8GB 主要承担小区域生成，主体结构/丝印/孔位来自 Blender。**不要把简单放大称为真实细节提升**。
- 主视图第二参考继续保留，但试验“第一参考 = 目标机位 PBR、第二参考 = 同产品主视图”与“仅第一参考”的对照，记录串色、视角带偏、耗时和显存。额外参考图不一定更好，也可能把主视角结构带到侧视。

### P2：仅在 P0/P1 通过后投入更昂贵方案

- 固定输入与种子，按顺序比较 768→896→992 的预算，再固定赢家比较 25→35→50 步。记录真实像素尺寸、峰值显存、耗时和结构评分；任一 OOM 或结构恶化即回退。原生 2K 优先用可控 API/更大显存机器验证，不在 4060 Ti 8GB 上直接设为默认。
- 官方 PE-I2I 仅作为可开关的“提示词草稿助手”：显示改写前后文本，人工批准后才进入任务。先测它是否保住 CAD 不变量；若把产品描述成不存在的按钮/纹理，拒绝该改写。8GB 本地可顺序卸载/CPU offload 或改用 API，不与生成模型常驻。
- 若主要瓶颈是高度精确的孔位/丝印/材质边界，停止盲目换更大生图模型，转向 Blender 完成主体 + 局部合成。若主要瓶颈是审美，再做布光、镜头、材质包贴图和设计预设 A/B。

## 五、最小 A/B 与验收门槛

| 实验 | 唯一变化 | 最小样本 | 观察项 | 通过后动作 |
|---|---|---:|---|---|
| A/B-1 提示词 | 当前长提示 vs 简洁编辑指令；CFG、种子、输入不动 | 2 机位 × 2 种子 × 2 版 = 8 张 | 孔位/分模线/材质错位、背景、整体可信度 | 仅优胜版进入八面组 |
| A/B-2 输入图 | 白模/配色引导 vs 已验收 PBR 底图 | 2 机位 × 2 种子 × 2 版 = 8 张 | 外形漂移与表面质感 | 底图胜出才考虑改默认 |
| A/B-3 双参考 | 单目标机位 vs 目标机位+主视图 | 2 困难机位 × 2 种子 × 2 版 = 8 张 | 身份一致、视角污染、耗时/显存 | 只在净收益明确时继续 |
| A/B-4 参数 | 固定种子，依次只改预算或步数 | 每档先 2 困难机位 | 实际像素、耗时、峰值显存、结构和美感 | 选择质量/成本最优档，不选最大值 |

每张人工评分：结构与方向 0–2、CMF 归属 0–2、材料可信度 0–2、背景/光照 0–2、视觉主次 0–2。**结构或 CMF 任一为 0，直接淘汰**；其余分数只用于合格图之间排序。至少完成两组不同种子的八面复验，才讨论“更稳定”。报告保留所有失败图和失败原因，不只展示精选图。

## 六、实施边界与回退

- 本轮**只新增方案，不改生产工作流/权重/默认参数**。先由 Windows 端拿同一真实产品完成 P0 小样；Mac 端代码自检不能替代 4060 Ti 的显存、速度或画质验收。
- 不直接下载/替换 BF16、GGUF 或额外 PE 权重；这会消耗大量磁盘、显存并改变可比性。先保留当前 INT8/W4A8 基线与原任务可回退。
- 原始 CAD、参考图、输出样张留在本机，公开仓库只上传脱敏的评分表和参数摘要。后续实现与验收结果继续登记在根目录过程文档。

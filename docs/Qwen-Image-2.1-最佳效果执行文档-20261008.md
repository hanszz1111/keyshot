# Qwen-Image-2.1 工业产品最佳效果执行文档

> 2026-10-08；状态：待 Windows 真机执行与人工盲评。本文件是执行路线，不代表最佳效果已经达成。目标设备 RTX 4060 Ti 8GB。

## 一、决策

质量优先采用 **3D 模型逐机位结构图与 PBR 基底 → Qwen 2.1 同机位材质/光影精修 → 局部掩膜保护 → 八面一致性筛选**。单面深度图不能约束背面；仅加步数、提示词或换大文本编码器也不能锁住真实几何。若 AI 改变轮廓、孔位、分模线、部件数量或 CMF 分区，退回 PBR 基底，不能选为成品。

当前保留实测可运行的 Qwen 2.1 INT8 主模型 + W4A8 文本编码器 + BF16 VAE，25 步 / CFG 1 / Euler + Simple。Windows [A/B 实测](AB实验-千问提示词与CFG首轮记录-20261008.md)显示：CFG 1 下负面词像素零作用；换 INT8 文本编码器未增强指令跟随，却增加约 27% 耗时、峰值显存达 95.3%。**不将 INT8 文本编码器、社区 shift=3.1、6 步 Turbo 或 1024 大图直接设为默认。**

## 三、P0：冻结基线与测试集

1. 保持正式 SDXL/结构实例 `8188`、Qwen 实验实例 `8190` 隔离；不直接改 `packs` 或覆盖原权重，也不并发两个 GPU 作业。记录项目 commit、ComfyUI 版本、模型 SHA-256、驱动、峰值显存。
2. 选 3 个获准测试的产品：明显孔/按键/分模线、多曲面、双色或三材质。每个先测正面、左前 3/4、右前 3/4、俯视、仰视；最终补齐八面。相机位置、投影、构图边距固定。
3. 每个机位生成同 SKU、同机位、同尺寸的 `clay/depth/normal/object_id/PBR`，保存 manifest。错机位、过期或缺少结构图必须阻断，绝不能用正面深度代替 3/4。
4. 冻结种子 43/1234、768 像素预算、25 步、CFG 1；利用 `scripts/qwen_ab_experiment.py` 保存参数、输入哈希与盲评网格。图像差异按解码像素比较，不能只比 PNG 文件哈希（元数据会变）。

**通过门槛：**所有机位 pass 完整、PBR 相机和部件分区正确、结果可追溯。否则先修 3D 导入/相机/材质映射，而非调采样。

## 四、按顺序做受控实验

### P1：输入图决定上限

同机位同种子比较 A 当前白模/深度引导、B 准确 CMF 的 PBR 基底、C PBR 基底+同一产品身份/材质参考；其余参数全部相同。第二参考不得把正面相机“带入”侧面。先比轮廓、孔位、分模线、配色区域，再比工艺和美感。若 B/C 稳定更准，将其作为 Qwen 精修入口；否则先修 PBR 图。

### P2：shift 仅作 A/B

在复制的 API 工作流中把 `ModelSamplingAuraFlow` 插在加载模型和采样之间，仅比较当前内置 `0.69` 与显式 `3.1`；先用两个难机位×两个种子×两臂，必要时扩到三 SKU。记录盲评、耗时、显存、失败样张。`3.1` 来自其他 Qwen 模板，并非已证实的 Qwen 2.1 最优值；σ 差异也不是画质证明。若无稳定收益或更易变形/OOM，保留 `0.69`。不得同时改步数、CFG、编码器。

### P3：8GB cache/分辨率

在隔离 8190 比较 `QwenImage21Cache` 关闭、CPU 与可用时 INT8 cache。先固定 768，测输出变化、峰值显存和耗时，再逐级试 896。仅当无 OOM、结构不降、显存留余量才开放更高预算。采样分辨率与最终导出放大分开；高像素不等于真实结构细节。

### P4：局部编辑与多部位材质（质量主功能）

先复用现有 `scripts/roi_crop.py` / `scripts/composite_masked.py` 做确定性裁切与拼回，在隔离实例测试 Qwen ROI 编辑；不足时再评估作者仓库 `ComfyUI-Inpaint-CropAndStitch`。第三方节点须固定 commit、审源码/依赖、备份环境，不安装到正式 8188。用 `object_id` 将前壳塑料、握持胶皮、金属饰件映射到 UI 高亮和材质表；允许多选但每个部件独立记录材质、色号、粗糙度。用户涂抹边界不确定时要求确认。

测试仅改其中一块：掩膜外像素须不变（若有色彩转换，记录可解释误差），拼接缝不可见，分模线连续，机位和颜色区域不漂。现有 Qwen API 工作流没有掩膜输入，不能只加 UI 开关就宣称完成；先做好后端链路、失败回退与测试。扩图只能改背景，产品本体锁定。

### P5：Viggle Turbo 只作速度档

`viggle_turbo.py` 与 LoRA 先做源码、来源、哈希、许可和 INT8 兼容性审查，仅在实验副本试 6 步；与 25 步基线使用同输入/机位/种子盲评。只有结构/CMF 不降且时间显著减少才开放“快速预览”，绝不默认成“最佳画质”。社区人像 LoRA 与 UI 便利节点不随工作流整包安装。

## 五、验收、修改和回退

两人盲评，分歧第三人复核；每张 0–2 分评结构、机位、CMF、工艺光影、背景洁净。另标致命错误：新增/丢失零件、左右互换、俯仰不正、跨视角换色、脏背景遮挡。一个 SKU 八面排成 2×4 总览，先判“同一个产品”，再判单张美感。

阶段晋级条件：三 SKU、两种子测试中**致命结构/CMF 错误为 0**，各项均分 ≥1.5/2，且优于基线；否则只保留实验选项，不改默认。这是小样门槛，不是普适保证。每轮只改一个变量；失败立即回退上一验证配置，原权重及 8188 不动。

实施文件：结构与机位校验在 `web/server.py`；Qwen API 节点在 `config/comfy_workflow_qwen21_edit.json` 的实验副本；UI 在 `web/index.html` / `web/app.js` 增加真正可用的“快速预览/精细成品”、多材质选区、预计时间与不可用原因；回归增加错机位、缺节点、掩膜外不变、八面 CMF、8GB OOM 回退。**社区 UI 工作流 JSON 不能直接当 `/prompt` API JSON**；需检查参考图点号键、latent 接线与节点可用性。每阶段独立提交，`web/selftest.py` 与专项测试全过后才合入。

Windows 端把每阶段的 commit、SKU/机位/种子、唯一变化、成功数/OOM、中位耗时、峰值显存、盲评分、致命错误、失败样张和回退结论回填 `AI/RESULT.md`；由 `AI/REVIEW.md` 复审。只上传脱敏统计和获准公开样张，不上传私有产品图。**在八面盲评及回退验证完成前，不宣称“最强形态”或“八面一致已解决”。**

# AI 白模渲染器 · 技术方案

> 版本 v1.0 ｜ 2026-09-19
> 输入：产品白模（KeyShot / Blender / STEP 转出）+ 文字描述 / 参数卡 / 参考产品图
> 输出：可用于电商主图与详情页的写实渲染图（可批量、多视角、多风格、中英双版）

---

## 一、需求拆解

你的原始诉求可以拆成 5 件事，每件事的技术难度和成熟度完全不同：

| # | 需求 | 技术归属 | 成熟度 | 判断 |
|---|---|---|---|---|
| 1 | **自动化渲染模型**（白模进去，图出来，批量） | 引擎 headless + 任务队列 | ★★★★★ | 纯工程，无风险 |
| 2 | **描述外观 / 材质 / 光照** | 提示词工程 + 参数卡 + ControlNet/IC-Light | ★★★★☆ | 主力路线，已可生产 |
| 3 | **给参考图仿照渲染** | IP-Adapter / FLUX Redux / 蒙版限定 | ★★★★☆ | 已可生产，可控性需要调试 |
| 4 | **模型上真 PBR 材质** | DreamMat / Hunyuan3D-2.1 / TRELLIS.2 | ★★★☆☆ | 能跑，但慢且许可受限 |
| 5 | **细节零失真**（丝印 / 刻度 / LOGO / 透明件） | 无纯 AI 方案 | ★★☆☆☆ | **必须靠后处理回贴，不能指望 AI** |

> **核心判断**：第 5 项决定了整个方案的架构。任何"纯 prompt 生成产品图"的方案在你这个类目（激光水平仪、气体检测仪 —— 刻度盘、按键、LOGO、透明视窗、镜面金属）都会翻车。所以本方案把 AI 定位为 **"材质与光影的生成器"**，把 **"形状与标识的保真"** 交给 3D 引擎和后期合成。

## 二、总体架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ L5 交付层   PSD 详情页占位替换 / 命名规范 / 中英双版 / QC 抽检          │
├──────────────────────────────────────────────────────────────────────┤
│ L4 后处理层  抠图(BiRefNet) → 超分(Real-ESRGAN) → LOGO丝印回贴 → 色彩统一│
├──────────────────────────────────────────────────────────────────────┤
│ L3 生成层    ComfyUI 工作流                                            │
│              结构控制(ControlNet depth/normal/canny)                   │
│            + 参考注入(IP-Adapter / FLUX Redux，可蒙版限定部位)          │
│            + 重打光(IC-Light) + 材质 LoRA + 采样                        │
├──────────────────────────────────────────────────────────────────────┤
│ L2 结构层    KeyShot headless  /  Blender(-b -P)  /  BlenderProc        │
│              批量出多机位多通道 Pass：beauty / depth / normal / alpha    │
├──────────────────────────────────────────────────────────────────────┤
│ L1 输入层    LLM 参数解析：自然语言 ─┐                                  │
│                                参数卡 JSON ─┼─▶ 渲染参数卡（统一结构）    │
│                                参考图 ─────┘                            │
├──────────────────────────────────────────────────────────────────────┤
│ L0 资产层    白模库 / 参考图库(材质·打光·构图) / 相机机位预设 / 提示词模板 │
└──────────────────────────────────────────────────────────────────────┘
```

**数据流（单张图）**

```
白模.ksp
  │  KeyShot headless（或 Blender）
  ▼
beauty.png + depth.png + normal.png + alpha.png     ← 2048 长边
  │
  ▼  ComfyUI（常驻 8188 端口）
  │   ① depth   → ControlNet  权重 0.55–0.75   ← 锁体积关系
  │   ② normal  → ControlNet  权重 0.35–0.50   ← 锁曲面朝向 / 高光走向
  │   ③ 参考图   → Redux / IP-Adapter  0.5–0.8  ← 注材质与影调
  │   ④ prompt   → 材质 + 光照 + 背景 + 镜头
  │   ⑤ IC-Light → 按指定方向重打光（可选）
  ▼
raw_1024.png
  │  后处理：抠图 → 精修 → 超分 2–4x → LOGO/刻度回贴
  ▼
{类目}_{SKU}_{视角}_{风格}_{版本}_{语言}.png
```

## 三、关键路线对比与选型

### 3.1 三条路线

| 维度 | A. 2D 图像侧 | B. 3D 材质侧 | C. 引擎内置 AI |
|---|---|---|---|
| 代表工具 | ComfyUI + ControlNet + Redux + IC-Light | DreamMat / Hunyuan3D-2.1 / TRELLIS.2 | KeyShot 2026.1 AI Shots |
| 单张/单模型耗时 | 6–30s（+20–40s 放大） | 10min–1h 每模型 | 数十秒 |
| 形状保真 | 高（ControlNet 锁） | 极高（真几何） | 中 |
| 材质真实度 | 中（是"像"，不是"是"） | 高（真 PBR 贴图） | 中高 |
| 多视角一致性 | 需固定 seed + 同一参考图 | 天然一致 | 天然一致 |
| 可批量编排 | ★★★★★ | ★★☆ | ★☆☆ |
| 许可风险 | 低（MIT/Apache 为主） | **高（Hunyuan3D/Pixal3D 非商用）** | 商业软件内，无额外风险 |
| 显存门槛 | 12–24GB | 24GB+ | 无（本地但已优化） |

### 3.2 选型结论

- **主力：路线 A。** 覆盖 80% 出图需求，速度是路线 B 的 50–200 倍，可编排、可版本控制、可回滚。
- **补充：路线 B 只用于「材质可信度要求极高」或「必须出一整套多视角」的单品。** 每个模型单独跑一次即可，产出 PBR 贴图后回灌 KeyShot 真渲染，或者把生成的多视角图当作路线 A 的参考图用。**注意：Hunyuan3D-2.1 权重为非商用许可，TRELLIS.2 是 MIT，DreamMat 是 MIT —— 商用优先用后两者。**
- **兜底：路线 C。** 你本来就在用 KeyShot，2026.1 的 AI Shots 支持本地跑、Transform 模式（按提示词改已有渲染图）、Replace 模式（画蒙版局部改），适合少量精品单件精修，不适合编排进流水线。

### 3.3 「参考图仿照」的三种强度（重点需求）

你说的"给一个类似的产品进行仿照渲染"，实际上有三种完全不同的强度，必须在参数卡里区分：

| 强度 | 目标 | 实现 | 参数 |
|---|---|---|---|
| **L1 风格轻参考** | 只借色调、影调、氛围 | IP-Adapter Plus | weight 0.4–0.6 |
| **L2 材质参考** | 借某个具体部位的材质质感（如"参考图那个磨砂壳"） | FLUX Redux + 蒙版限定 | `downsampling_factor` 2–3，`mode=autocrop with mask` |
| **L3 整体仿照** | 连打光带构图一起学 | FLUX Redux 高权重 + 图生图 | `downsampling_factor` 1–2，denoise 0.5–0.7 |

> ⚠️ FLUX Redux 原版有个坑：**高权重时它会完全忽略你的提示词**（只复刻参考图）。解决方式是加 `ComfyUI_AdvancedRefluxControl`，用 `downsampling_factor` + `weight` 把"复刻参考图"和"听提示词"这两个力掰开。这是把 Redux 当 IP-Adapter 用的关键一步。

## 四、L2 结构层：Pass 输出规范

白模必须输出**多通道**，不是只出一张灰模图。这是整个方案里最容易被忽略、又最影响成品率的一环。

| Pass | 用途 | 格式 | 说明 |
|---|---|---|---|
| **Beauty（灰模）** | 底图参考、后续 Canny 来源 | PNG 16bit | 统一 0.8 中性灰，无材质，可保留基础 AO |
| **Depth** | ControlNet Depth | PNG 8bit（归一化）或 EXR | 近白远黑；EXR 更好，可自己归一化 |
| **Normal** | ControlNet Normal | PNG RGB | OpenGL 约定（Y+ 朝上），和 ControlNet 训练集对齐 |
| **Alpha / Mask** | 抠图、局部重绘、蒙版限定参考 | PNG 8bit | 主体蒙版必出，省掉后期抠图 |
| **AO / Curvature**（可选） | 强化倒角、缝隙、按键细节 | PNG | 对仪表类产品提升明显 |
| **Lineart**（可选） | 硬结构约束（刻度、棱边） | 由 beauty 后处理生成 | 不额外出，用 Canny/Lineart 预处理器现算 |

**分辨率策略**：Pass 出 **2048 长边**（留超分余量），中间图出 **1024–1536**，最终交付 **2048–4096**。

**实现选择**：

| 方式 | 优势 | 劣势 | 建议 |
|---|---|---|---|
| **KeyShot headless scripting** | 你已有 KeyShot 资产和材质库；HDR 环境、相机、模型集都能脚本控制 | Headless scripting 是 **Pro 独占功能**，需要 9.3+；深度/法线通道支持有限 | **主用**，用于 beauty 与相机编排 |
| **Blender `-b -P`** | 完全免费，AOV/Compositor 出 depth/normal 最灵活 | 需要重建或导入资产，材质库不通 | **用于 pass 生成**，把白模导入 Blender 出 depth/normal |
| **BlenderProc** | 已封装 RGB/depth/normal/seg 输出，yaml 配置，`pip install blenderproc` | 偏合成数据场景，需要写少量 Python | 想省事就直接用它 |

**推荐组合：KeyShot 出 beauty + 定机位；Blender/BlenderProc 出 depth/normal/alpha。** 两边都用同一个相机参数（焦距、机位、朝向），保证像素级对齐 —— **Pass 不对齐 = ControlNet 直接失效**，这条务必验证。

## 六、L3 生成层：ComfyUI 工作流

### 6.1 基线配置（建议从这个开始）

| 环节 | 选型 | 参数 |
|---|---|---|
| 底模 | FLUX.1-dev fp8 / Qwen-Image / SDXL-Lightning（快出草稿用） | — |
| ControlNet-Depth | FLUX depth 或 controlnet-union-sdxl | weight 0.55–0.75，end 0.6–0.7 |
| ControlNet-Normal | 对应底模的 normal 模型 | weight 0.35–0.50，end 0.5–0.6 |
| 参考注入 | FLUX.1-Redux-dev + AdvancedRefluxControl | factor 2–3 |
| 参考注入（备选） | IP-Adapter Plus | weight 0.5–0.8 |
| 重打光 | IC-Light（fc / fbc） | 见下 |
| 采样 | euler / dpmpp_2m | Flux: steps 20–28, cfg 1.0；SDXL: steps 25–30, cfg 7.0 |
| 高清修复 | latent upscale 1.5x + denoise 0.3–0.4 | 或 Ultimate SD Upscale |
| 放大 | Real-ESRGAN 或 Topaz | 2–4x |
| 抠图 | BiRefNet | 输出带 Alpha |

### 6.2 参数调优的顺序（踩坑顺序）

调参不要平行调。按这个顺序逐层锁定：

1. **先只开 Depth**，权重从 0.6 起，调到"轮廓和厚度关系一眼对"。这一步不过关，后面全部白搭。
2. **加 Normal**，权重从 0.35 起，观察曲面高光走向是否合理（金属拉丝方向、球面反射）。**Normal 权重过高会让画面发"塑料感"和"死灰"，超过 0.5 就要警惕。**
3. **加参考图**，先低权重（Redux factor 3 / IP-Adapter 0.5），确认只借了影调没借错形状。
4. **最后调 prompt**。到这一步 prompt 只负责材质词和氛围词，不负责形状。**如果你发现要写很长的形状描述才能出对图，说明 ControlNet 没调好，回去调第 1 步。**
5. **打光**单独一轮，用 IC-Light 或直接改 KeyShot 的 HDR 重出 beauty。

### 6.3 IC-Light 的定位与坑

IC-Light 是"重新打光"模型，不是"生成"模型。用法：

- `iclight_sd15_fc`：纯文本条件，无背景图输入时用，最稳。**推荐首选。**
- `iclight_sd15_fbc`：背景条件，有背景图输入时用。**已知坑：会把背景颜色"渗"到主体上**，产品图上很容易出现壳子被背景染色。如果遇到，就退回用 `fc` 并把背景写在 prompt 里。
- `fcon` 不用下（训练加了 offset noise，效果不如 fc）。
- 模型放 `ComfyUI/models/unet/`。

> 更稳的做法：**别用 IC-Light，直接在 KeyShot 里换 HDR 环境重出 beauty**。你已经有 KeyShot 管线，用真三维光照重出底图，比让 AI 猜光照可靠得多。IC-Light 只用在"手里只有一张现成图、要改光"的场景。

## 七、L4 后处理层（决定成品率的一层）

| 步骤 | 工具 | 作用 |
|---|---|---|
| 抠图 | BiRefNet | SOTA 边缘，透明件/发丝级细节，比传统抠图强一个量级 |
| 结构对齐校验 | OpenCV 叠图 diff | 生成图 vs 白模 beauty，算轮廓偏移，超阈值打回重跑 |
| 超分 | Real-ESRGAN / Topaz | 2–4x |
| **LOGO / 丝印 / 刻度回贴** | Photoshop 脚本 / PSD 图层 | **最关键**。从 AI 图里取光照和材质，把矢量 LOGO 用"正片叠底/叠加"贴回去 |
| 色彩统一 | LUT / 直方图匹配 | 同一 SKU 多张图色调一致 |
| 合规校验 | 人工 + 清单 | 防止生成出与实物不符的结构（虚假宣传风险） |

> **"LOGO 回贴"这一步必须进流程。** 激光水平仪机身上的丝印品牌、气体检测仪面板上的刻度和认证标识，AI 100% 会糊或写错字。正确做法是：**AI 只出"有材质的壳体"，文字和刻度作为独立图层在 PS 里叠上去**。这一步用脚本跑批，成本很低（见图层脚本模板）。

## 八、自动化调度

### 8.1 组件拓扑

```
┌─────────────────┐
│ 任务队列 (SQLite) │  ← 参数卡列表 + 状态 + 重试次数
└────────┬────────┘
         │
    ┌────┴─────┐
    ▼          ▼
┌────────┐  ┌──────────────┐
│ KeyShot│  │ ComfyUI 常驻  │  http://127.0.0.1:8188
│headless│  │ (--listen)    │  POST /prompt → poll /history/{id}
└────────┘  └──────────────┘
                 │
            多卡：启动多个实例，不同端口 8188/8189，队列侧轮询分发
```

### 8.2 为什么必须"常驻服务 + HTTP 队列"，不能循环起进程

- ComfyUI 冷启动 10–30s。循环起进程跑 4800 张 = 白扔 13–40 小时。
- 常驻一次，任务在内部排队，吞吐差 2–3 倍。
- 多卡时一个实例吃满一张卡的显存，跑两个实例反而比单实例多卡调度更快（避免显存抖动）。**实测经验值：多卡独立实例比单实例多卡快 2–3 倍。**

### 8.3 关键工程点（都是踩过的坑）

| 坑 | 表现 | 解法 |
|---|---|---|
| 工作流 JSON 格式错 | API 报 KeyError on node ID | 必须开 **Dev Mode → Save (API format)**，节点 ID 是数字，不能用 UI 格式导出 |
| `/history` 查不到在途任务 | 以为失败了 | `/history` 只返回**已完成**任务，在途任务不出现。必须轮询直到 `prompt_id` 出现，**第一次查不到不等于失败** |
| 节点静默失败 | 队列卡住不报错 | 节点 CUDA 报错时不会通过 API 返回，会静默堵队列。必须**读 ComfyUI 终端日志**判断，并设超时 |
| 服务器重启丢历史 | 长批次中断 | `/history` 在 ComfyUI 重启后清空 → **把 prompt_id 持久化到 SQLite**，重连后续跑 |
| 输出路径 | 拿到相对路径 | API 返回相对路径，实际写绝对路径。启动时用 `--output` 指定输出目录 |
| 显存瓶颈 | 1080p 时 3 个 ControlNet 爆显存 | 1024 可叠 3 个，1536 实际只能叠 2 个（24GB 卡） |

## 九、效率与成本估算

### 9.1 单张耗时（RTX 4090 24GB，1024×1024）

| 配置 | 耗时 |
|---|---|
| SDXL + 2 ControlNet + IP-Adapter | 6–10s |
| FLUX dev fp8 + 2 ControlNet + Redux | 18–30s |
| 上面 + 2x 放大 | +20–40s |
| 后处理（抠图 + 回贴 + 命名） | 5–15s |

### 9.2 产能推算

| 场景 | 数量 | 单卡耗时 |
|---|---|---|
| 1 个 SKU，5 视角，每视角 4 张候选 | 20 张 | 10–25 分钟 |
| 100 个 SKU 全套 | 2000 张 | 14–28 小时 |
| **800 个 SKU 全套** | **16000 张** | **约 5–11 天（单卡）** |
| 同上，双卡 | — | 2.5–5.5 天 |

> **先出 1024 草稿筛选，选中的 20% 才做超分**。这一条能把总机时砍掉 60% 以上。

### 9.3 成本对比

| 方案 | 800 SKU 全套成本 |
|---|---|
| 本地自建（已有 4090） | 电费 + 维护，边际成本 ≈ 0 |
| 外包摄影修图 | ¥150–400/张 × 16000 ≈ **¥240–640 万** |
| 云 GPU 租用（AutoDL/RunPod） | 约 ¥1.5–3/小时 × 200–260 小时 ≈ **¥300–800** |
| 商业 API（Kontext Pro $0.04/张） | 16000 × $0.04 ≈ **$640（约 ¥4600）**，且不可控性更高 |

**结论：本地自建 ROI 极高，回本周期以"天"计。** 唯一的隐性成本是调参与维护人力。

## 十、分阶段落地路线

### P0 · 可行性验证（3–5 天）

## 十一、风险清单

| # | 风险 | 等级 | 应对 |
|---|---|---|---|
| 1 | **丝印 / LOGO / 刻度错乱** | 🔴 高 | 不靠 AI，走"图层回贴"。AI 只出壳体材质 |
| 2 | **透明件（亚克力视窗）崩坏** | 🔴 高 | 降低 AI 占比，透明件区域用 KeyShot 真渲染后合成；或 AI 出完再贴真渲染层 |
| 3 | **镜面金属反射出现"幽灵物体"** | 🟠 中 | ControlNet normal 权重提到 0.45+；prompt 里明确 "clean reflective surface, no reflections of objects" |
| 4 | 同款多图一致性差 | 🟠 中 | 固定 seed 组 + 同一参考图 + 提示词骨架只换风格词 |
| 5 | Pass 与成图不对齐 | 🟠 中 | 相机参数单一来源；P0 必须验证；建立叠图 diff 自动校验 |
| 6 | 开源模型许可 | 🟠 中 | 商用只选 MIT/Apache：TRELLIS.2、DreamMat、BiRefNet、Real-ESRGAN；FLUX dev 商用需看 BFL 条款 |
| 7 | **生成图与实物不符 → 广告合规** | 🔴 高 | QC 清单强制比对实拍照片；关键参数（量程/精度/认证标识）禁止 AI 生成 |
| 8 | 显存溢出导致批次中断 | 🟡 低 | 断点续跑 + 超时重试 + 分批降分辨率 |
| 9 | 调参人力黑洞 | 🟠 中 | 参数卡固化为预设，每类目一套，不再逐张调 |

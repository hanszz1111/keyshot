# P0 形准验证方案

> # ⚠️ 已归档 · 关键门槛已被实测证伪（快照 2026-09-19，v1.0）
>
> **本文写的 `IoU ≥ 0.90` 硬门槛，在 2026-09-27 实测中平均只有 0.330。**
> 但该结果**不是失败证据** —— 而是**证明这个指标在本场景失效**：白模背景近黑、
> AI 成图是影棚亮背景，浏览器端「四角底色扣除」把 AI 新增背景算作前景，导致剪影虚高、交集偏低。
>
> **更重要的是：本文假设"过不了 0.90 就暂停方案"，实际结论恰恰相反** ——
> 轮廓与大体块确实守住了（肉眼可辨认为同一产品），真正的问题是**表面细节守不住**
> （AI 臆造 CAD 中不存在的格栅/孔点/罗纹）。**所以方案没有暂停，而是转向 ADR-015：产品本体走真渲染。**

## 0. 一句话

P0 只回答**一个问题**：

> **只给一张 depth 图、prompt 里一个形状词都不写，AI 能不能生成「一眼认出是同一台仪器」的图？**

- **能** → 继续投 P1。
- **不能** → **停下查根因，不要调 prompt。** prompt 治不了这个问题。

**这一条是全项目唯一的硬门槛。不过则整个方案暂停。**

---

## 1. 为什么它是唯一的一票否决项

整条产线的所有环节（KeyShot 出 pass、Blender 出 depth/normal、参数卡、任务队列、后处理、PSD 对接）都建立在一个假设上：

> **depth/normal 能把「形状」这件事彻底锁死。**

如果这个假设不成立，那么后面所有工程量都是在一条错误的路上做优化 —— 做得越精细，浪费越大。

**所以先用最小代价（1 个 SKU、3 个视角、约 20 张）把它证伪或证实。**

判据来自 00 文档 4.4：**像素级对齐是一切的前提**。

## 2. 前置条件

### 2.1 环境（本机适配版）

| 项 | 本机方案 | 说明 |
|---|---|---|
| 引擎 | **ComfyUI 官方 Windows 便携版** | 自带 Python 3.13 + PyTorch CUDA，解压即用。本机**没有 git / pip**，这是唯一低摩擦路径（15.3） |
| 落盘位置 | **F 盘**（剩 212GB） | 引擎 + 模型约 20–30GB |
| 启动 | 双击 `run_nvidia_gpu.bat` → `http://127.0.0.1:8188` | 若 8GB 显存吃紧，改 `--lowvram` |
| 控制台 | `启动控制台.bat` → `http://127.0.0.1:8765` | 投放区 / 参数卡 / 对齐校验（引擎 8188 与控制台 8765 不冲突） |
| 插件 | `comfyui_controlnet_aux`（出 depth/normal 预处理）+ `ComfyUI-Manager` | P0 阶段**不需要** IC-Light / IPAdapter，别一次装 4 个 |
| KeyShot | ≥ 9.3 且为 **Pro**（headless 是 Pro 独占） | P0 只出 1 个 SKU 的 clay，**手点即可**，不必写脚本 |

### 2.2 模型清单

| 模型 | 用途 | 大致体积 | 为什么是它 |
|---|---|---|---|
| **SDXL 写实底模**（RealVisXL / Juggernaut 一类） | 底模 | ~6.5GB | 8GB 显存的现实选择（15.4） |
| **`controlnet-union-sdxl-1.0`** | depth + normal 一个模型全包 | ~2.5GB | 省显存、省下载；节点里用 `Set Union ControlNet Type` 切 depth / normal |
| VAE | 解码 | ~0.3GB | 部分底模内置，缺了才装 |

> ⛔ **不要下 FLUX.1 [dev]。** 两个原因：① 8GB 跑不动「FLUX + ControlNet」组合（峰值 20–22GB）；② **它的权重是非商用许可**，本地跑商用图不合规（15.5）。
> ⛔ 不要下 Hunyuan3D-2.1 / Pixal3D 权重（非商用 / 学术许可）。

### 2.3 素材：选哪个 SKU 练手

**选型原则（按重要性排序）**：

1. **结构简单** —— 方壳 + 少量按键，别选曲面复杂、多部件拼装的
2. **⛔ 绝对不要有透明件**（透明亚克力视窗）—— AI 对透射材质能力不足，会把透明件变成灰块，**这属于已知的边界问题，不是形准问题**，混进来会污染本次验证结论
3. **⛔ 不要镜面抛光金属** —— 同理，属于已声明的「不用 AI」场景
4. 最好已有实物照片，方便做「生成图 vs 实物」比对
5. **深度关系有辨识度** —— 有前凸的镜头 / 凹陷的按键 / 明显的前后层次，这样 depth 才有信息量；一个纯方盒子 depth 全是平面，验不出东西

**推荐**：一台**哑光 ABS 外壳 + 少量按键**的激光水平仪（如 LS-360G 这类），3 个视角。

**视角选择**：`front`（正面）/ `3q4_left`（左前 45°）/ `side`（侧面）。**必须有一个非正交视角** —— 纯正视图验不出厚度。

## 3. 执行步骤

### Step 0 · 落地环境（0.5 天）

1. 下 `ComfyUI_windows_portable_nvidia.7z` → 解压到 `F:\ComfyUI\`
2. 双击 `run_nvidia_gpu.bat`，浏览器开 `127.0.0.1:8188`，看到默认工作流 = 成功
3. 装插件：`comfyui_controlnet_aux`（Manager 搜或手工丢进 `custom_nodes/`）
4. 模型按 2.2 放进 `ComfyUI/models/checkpoints|controlnet|vae/`

**验收**：能用默认工作流空跑出一张图（哪怕很丑）。

> ⚠️ 8GB 显存专项：若启动报显存不足，把 `run_nvidia_gpu.bat` 里的启动参数加上 `--lowvram`，并在 VAE Decode 节点开 **tiled decode**（分块解码）。

### Step 1 · 出 pass（1 天）

按 **ADR-009**：**KeyShot 出 clay（beauty），Blender 出 depth / normal / alpha。**

| 通道 | 出处 | 格式 | 要求 |
|---|---|---|---|
| `clay` | KeyShot | PNG 2048 长边 | 统一灰材质，无贴图 |
| `depth` | Blender | PNG 8bit 归一化（或 EXR） | 近白远黑，**归一化方向要对** |
| `normal` | Blender | PNG RGB | ⚠️ **必须确认是相机空间**（通常 OpenGL：X 右 / Y 上 / Z 朝观察者） |
| `alpha` | Blender | PNG | 抠图用 |

**⛔ 相机参数必须完全一致**：焦距、机位、朝向、目标点。**Pass 不对齐 = ControlNet 直接失效**（4.4）。

**落盘位置**：按 00 文档 10.6 的投放区约定，直接丢进

```
assets/passes/LS-360G/front/{clay,depth,normal,alpha}.png
assets/passes/LS-360G/3q4_left/…
assets/passes/LS-360G/side/…
```

**验收**：控制台「投放区」里每个机位都显示 **`clay` + `depth` + `normal` 三件齐**（缺件会标红）。

### Step 2 · 先查 pass 对齐（0.5 天）—— **最容易漏、也最致命**

**在跑 AI 之前**，先把 `depth` 和 `clay` 叠起来看：

- 用控制台的「对齐校验」（浏览器内算 IoU，图片不上传），或 PS 里 `depth` 图层设为「差值」混合模式
- **边缘偏移必须 < 2px**
- `depth` 和 `normal` 之间也必须对齐（同一相机出的，理论上必然对齐；不对齐说明导出环节串了）

**⛔ 这一关不过，后面全是浪费时间。**

### Step 3 · 搭最小工作流（0.5 天）

**只开 Depth 一个 ControlNet，不要叠 normal，不要 Redux，不要 IC-Light。**

```
Load Checkpoint (SDXL 写实底模)
        │
        ├──▶ CLIP Text Encode (positive)  ┐
        └──▶ CLIP Text Encode (negative)  │
                                          ▼
Load Image (depth.png)            ControlNet Apply (Advanced)
        │                                 │
        ▼                                 │
Set Union ControlNet Type = depth ────────┘
                                          │
Empty Latent (1024 × 1024) ──▶ KSampler ◀─┘
                                   │
                              VAE Decode (tiled)
                                   │
                              Save Image
```

**参数基线**（来自 00 文档 9.2）：

| 参数 | 值 | 说明 |
|---|---|---|
| ControlNet Depth strength | **0.65**（区间 0.55–0.75） | 太高会「糊成灰模」，太低锁不住形 |
| end_percent | 0.7 | 让后段自由发挥质感 |
| steps | 24–30 | |
| cfg | 5–7 | |
| sampler | `dpmpp_2m` 或 `euler` | |
| 分辨率 | **1024 × 1024** | 8GB 不要上 1536 |
| seed | **固定基数**（如 12345） | 便于对比不同参数 |

### Step 4 · 写 prompt（**关键动作**）

按 00 文档 9.5 的结构公式拼，**但故意不写任何形状/结构描述**：

**✅ 写**：材质、光照、背景、镜头语言
**⛔ 不写**：几个按键、按键在哪个位置、屏幕形状、刻度、型号、任何数字

示例（激光水平仪 · 3/4 左前）：

```
positive:
professional product photography of a compact laser level instrument,
matte dark grey ABS housing, brushed stainless steel accent ring,
soft large softbox light from upper left, subtle rim light,
seamless light grey studio background, high detail, sharp focus,
commercial catalog shot

negative:
text, letters, numbers, logo, markings, watermark, blurry, low quality,
extra parts, deformed, fused, plastic looking metal, background color bleeding
```

> **为什么故意不写形状词**：形状描述词是 AI 最不可控的输入，会与 ControlNet 信号对抗。**我们要验的是「ControlNet 单独能把形状锁到什么程度」**，掺进 prompt 就没法归因了。

### Step 5 · 出图（0.5 天）

- 每个视角出 **2 张**（换 seed，如 12345 / 12346）
- 共 **3 视角 × 2 张 = 6 张**
- 8GB 预期：**60–120s / 张**，全部跑完约 **10 分钟**
- 建议再加跑 **3 张「无 ControlNet 对照」**（同 prompt，不带 depth）→ 用来证明「形准是 ControlNet 的功劳」，这是**最有说服力的证据**

## 4. 判据（三层，必须全过）

### 4.1 第一层 · 肉眼（**主判据**）

把 **白模 / 生成图** 并排放在一起，问三个问题：

| # | 问题 | 通过标准 |
|---|---|---|
| 1 | 轮廓形状对得上吗？ | 长宽比、倒角、凸起位置一致 |
| 2 | **厚度 / 纵深关系**对吗？ | 不能把圆柱压成方的，不能丢倒角，前凸件要凸出来 |
| 3 | 按键 / 旋钮 / 接口的**数量和位置**对吗？ | 位置偏差不超过部件自身尺寸的一半 |

**判定**：**「一眼认定是同一台仪器」= 通过。** 有一处需要「凑近看才确认」= 不通过。

### 4.2 第二层 · IoU（~~**硬指标**~~ → ⚠️ 已被证伪，见文件头）

生成图与白模叠图，用控制台「对齐校验」算 IoU：

**~~IoU ≥ 0.90~~**

> ⚠️ **实测结果（2026-09-27）**：front 0.249 / 3q4_left 0.316 / 3q4_right 0.374 / side 0.382，
> **平均 0.330**。归因：白模背景近黑（灰度均值 16.9）vs AI 成图影棚亮背景（126.4），
> 浏览器端「四角底色扣除」把 AI 新增背景计入前景 → 剪影虚高、交集偏低。
> Python 端独立复算与浏览器端对 front 完全一致（均 0.249），互验通过。
> **结论：该指标在当前场景失效，不应作为能否继续的判据。**

### 4.3 第三层 · 结构清单核对

对照实物/白模列出关键结构点（建议 6–10 项，例如：镜头凸起、按键 A/B/C、电池盖、挂孔、螺纹接口），逐项打勾。

**通过标准：关键结构点错漏 ≤ 1 项，且不能是关键项。**

> ⛔ **三层全过才算 P0 通过。** 任一层不过 → 进第 6 节决策树。

## 5. 交付物

P0 结束必须能拿出这四样：

1. **对比图**：`白模 | 有 ControlNet | 无 ControlNet（对照）` 三联并排 × 3 视角
2. **对齐证据**：`depth` vs `clay` 的叠图 diff（偏移 px 数）+ IoU 数值
3. **参数记录**：实际用的 ControlNet 权重 / end / steps / cfg / sampler / seed
4. **结论一句话**：通过 / 不通过 + 若不通过，根因定位到哪一层（pass / 对齐 / 模型 / 参数）

---

## 6. 失败诊断决策树

> 按顺序排，**从上往下查**。多数问题在前两层。

| 症状 | 最可能的原因 | 第一个该动的地方 |
|---|---|---|
| ① 图整体像灰模，没材质 | ControlNet 权重过高 | depth 0.65 → 0.55；end 0.7 → 0.6 |
| ② 整体「胖了/瘦了/压扁了」 | **相机参数不一致** 或 depth 归一化方向反了 | **先查 Step 2 对齐**，再核 depth 黑白方向 |
| ③ 局部结构错乱（按键多了/少了/挪位） | depth 权重不够，或分辨率不足 | depth 提到 0.75；确认 1024 而非 512 |
| ④ 轮廓边缘「糊边」 | end_percent 太高 | end 0.7 → 0.55 |
| ⑤ 长得像同一类产品，但**不是同一台** | **depth 信息量不足**（视角太正 / 模型太方） | 换一个**非正交视角**重出 depth；检查 depth 是否真的区分了前后层次 |
| ⑥ 每次出图形状都不一样 | seed 未固定 / 工作流缓存串了 | 固定 seed；清 ComfyUI 缓存重跑 |
| ⑦ 金属反射里出现「幽灵物体」 | normal 权重问题（本阶段未开 normal，先忽略） | P1 再处理 |
| ⑧ 显存溢出、批次中断 | 8GB 不够 | 开 `--lowvram` + tiled VAE；降到 768 试；确保没有同时开别的吃显存程序 |

**⛔ 归因纪律**：**先怀疑 pass 和相机，再怀疑参数，最后才怀疑模型。** 反过来查会浪费几天。

## 9. 通过 / 不通过之后

### ✅ 通过

1. 回填 00 文档，附录 E 第 1 项置 ✅
2. 进 **P1**：加 normal、加参考图、加后处理、ComfyUI 常驻、SQLite 队列
3. 按 15.7 的路径：**本机打样定参 → 参数定死后，量产切 R-D 托管 ComfyUI**

### ❌ 不通过

1. **不要继续投 P1。** 按第 6 节定位根因
2. 如果根因是 **pass 或对齐** → 修，然后**重跑 P0**（成本很低，值得再试 1–2 轮）
3. 如果根因是 **depth 信息量不足**（换视角也没用）→ 说明该 SKU 类别不适合纯 depth 锁形，需要评估：
   - 加 normal 双 ControlNet（进 P1 前置验证）
   - 或改走 **3D 材质线（R-B）**
   - 或该类目直接回退真渲染
4. 无论哪种，**结论都要写回 00 文档**（第十一章 P0 状态 + 附录 E），避免下次重复踩

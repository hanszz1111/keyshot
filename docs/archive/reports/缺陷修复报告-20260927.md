## 一、缺陷 ① 模型导入无法使用

### 现象
导入 3D 白模后，生成的「结构图」各机位取景雷同，看不出是不同角度 —— 看起来像导入没生效。

### 排查过程

| 步骤 | 检查项 | 结果 |
|---|---|---|
| 1 | `/api/assets` 是否列出模型 | ✅ 6 个模型全部在列（`AI渲染1.3dm` / `GF.stl` / `GF(1).stp` / `stl.stl` / `stl_2.stl` / `stl_3.stl`） |
| 2 | Blender 是否可用 | ✅ `blender.exe` v4.5.0 |
| 3 | STL 能否导入并出 pass | ✅ 单次 3.58 秒成功 |
| 4 | **各机位参数是否不同** | ❌ **全部相同** |

### 根本原因

`web/server.py` 调用 `scripts/blender_pass.py` 时**只传 `--model / --sku / --view`**，从不传 `--azimuth / --elevation`。而脚本里这两个参数的默认值是**写死的 `(0.0, 12.0)`**：

```python
# 修复前（错误）
ap.add_argument("--azimuth", type=float, default=0.0)
ap.add_argument("--elevation", type=float, default=12.0)
```

→ **五个机位全部用同一组 `(0, 12)` 取景**。"正面"实际渲染成了瞄准器端面/俯视管状视图，三个 3/4 视角完全没有转弯。

### 修复

在脚本内建「机位 → (方位角, 仰角)」查表，参数默认改为 `None`，未显式给值时按 `--view` 取值：

```python
# 修复后
VIEW_ANGLES = {
    "front":         (0.0,    8.0),
    "3q4_left":      (-45.0, 15.0),
    "3q4_right":     (45.0,  15.0),
    "side":          (90.0,   8.0),
    "top":           (0.0,   80.0),
    "detail_keypad": (-30.0, 35.0),
    "detail_window": (30.0,  30.0),
}
...
default_az, default_el = VIEW_ANGLES.get(view, (0.0, 8.0))
if args.azimuth is None:   args.azimuth = default_az
if args.elevation is None: args.elevation = default_el
```

### 验证

| 机位 | 实测方位角 / 仰角 | clay 图表现 |
|---|---|---|
| front | 0 / 8 | 正面 |
| 3q4_left | -45 / 15 | 左前 3/4 |
| 3q4_right | 45 / 15 | 右前 3/4 |
| side | **90 / 8** | ✅ 正确侧面轮廓：滚花目镜 + 完整机身 |
| top | 0 / 80 | 俯视 |

## 二、缺陷 ② 图生图「基本没有渲染」

### 现象
上传产品图（深色底白模截图）→ 调改动幅度 → 出图与输入几乎一样，等于没渲染。

### 三重成因（均经量化确认）

#### 成因 2a：有效步数不足

Lightning 底模只有 **8 步**。旧默认 `denoise 0.45–0.50`：

```
有效步数 = round(8 × 0.50) = 4 步
```

DPM++ SDE 在 4 步内出不了有效渲染。

**量化证据**：输出直方图均值/标准差 **134.6 / 97.4**，输入 **134.5 / 99.0** —— 几乎完全一致；平均绝对像素差仅 **4.55 / 255**。

#### 成因 2b：裸 img2img 无形状约束 → 提高 denoise 就臆造

参数扫描（与源图的平均绝对像素差）：

| 配置 | MAE | 结果 |
|---|---|---|
| A 8步 / d0.50 | **4.55** | 无变化（原样返回） |
| B 8步 / d0.75 | **43.60** | 有渲染，但**臆造出一把雷达枪** |
| C 20步 / d0.60 | 8.36 | 仍不足 |
| D 30步 / d0.70 | 22.18 | 有渲染，但臆造水印 "Stuiio Product Deⅵer" |
| E 12步 / d0.65 | 13.78 | 中等 |

→ **裸 img2img 必然在「不渲染」与「臆造别的产品」之间二选一。**

#### 成因 2c：白模被当成成品照片

用户上传的是**深色背景上的白模/灰模截图**（1221×786，均值 134.5 / 标准差 99.0），但提示词按"成品照片"处理，没有告诉模型「这是未上色的白模，要把它变成有材质的成品」。

### 修复方案

#### (1) Canny → ControlNet 锁形状

`config/comfy_workflow_sdxl_img2img.json` 从 7 节点重写为 **13 节点**：

```
LoadImage(15) → ImageScale(5) → Canny(30) → SetUnionControlNetType(22) → ControlNetApplyAdvanced(20)
                   └→ VAEEncode(16) → KSampler(3).latent_image
```

| 节点 | 关键参数 |
|---|---|
| 30 Canny | `low_threshold 0.06, high_threshold 0.18` |
| 22 SetUnionControlNetType | `type = "canny/lineart/anime_lineart/mlsd"` ⚠️ 分组枚举 |
| 20 ControlNetApplyAdvanced | `strength 0.75, start_percent 0.0, end_percent 0.85` |
| 3 KSampler | `steps 12, cfg 3.0, dpmpp_sde/karras, denoise 0.85` |

> ⚠️ **坑**：`SetUnionControlNetType.type` 必须用**分组枚举字符串**。写 `"canny"` 会 HTTP 400：`value_not_in_list: 'canny' not in ['auto','openpose','depth','hed/pidi/scribble/ted','canny/lineart/anime_lineart/mlsd','normal','segment','tile','repaint']`

#### (2) img2img 专参

`config/render_defaults.json` 新增 `img2img` 块：`steps 12 / cfg 3.0 / dpmpp_sde / karras / denoise 0.55–0.95（默认 0.85）/ canny_w 0.75`。

#### (3) 白模检测 + 提示词改写

`web/app.js` 新增 `probeImage()`（96×96 画布采样）：

```javascript
clay = darkRatio > 0.25 && brightRatio > 0.10 && satMean < 0.12
```

命中时改写提示词，并追加 `NEGATIVE_CLAY`（压制「保持灰色/白模」），`_meta.input_kind = "clay"`。

#### (4) 前后端范围对齐

前端滑块 `min=35 max=90` → **`min=55 max=95 value=85`**（此前滑到 35–50% 会被服务端拒绝）。

### 对照实验结果

| 配置 | MAE | 剪影 IoU | 边缘 IoU | 结论 |
|---|---|---|---|---|
| N1 无 CN / 12步 / d0.85 | 56.58 | 0.784 | 0.059 | ❌ 形状全丢，臆造 "GRONAL" 标牌 + 水印 |
| **C1 CN0.75 / 12步 / d0.85** | **74.80** | 保留 | 0.118 | ✅ **推荐**：材质彻底换新 + 形状一致 |
| C2 CN1.00 / 12步 / d0.85 | 65.22 | 保留 | 0.133 | 偏保守，改动略不足 |
| C3 CN0.75 / 12步 / d0.70 | 41.55 | 0.822 | 0.178 | 改动不足 |

> **指标说明**：剪影 IoU 对「背景由深变亮」的场景失真 —— 白模背景近黑、成图是影棚亮背景，自适应阈值会把 AI 新增背景算作前景，导致 C1/C2 的 IoU 虚低。**判读以 MAE + 肉眼为准**。

### 端到端验证（真实链路）

走 `/api/tasks → /api/comfy/submit → /api/comfy/poll`：

| 项 | 值 |
|---|---|
| `mode` | **`img2img`** ✅ |
| 拓扑 | 13 节点，含完整 CN 链（Canny 0.06/0.18 → CN strength 0.75 / end 0.85） |
| 产出 | `outputs/stl_2/photo/ai_render_00027_.png` |
| 耗时 | 约 **28 s** |
| 形状 | ✅ 保留大窗口轮廓 / 下部格栅弧线 / 机身分模线 / 滚花目镜 / 顶部红键 |
| 材质 | ✅ 哑光黑工程塑料 + 银金属滚花目镜，真实影棚光照与接触阴影 |
| 臆造标识 | ✅ **无** |

### 附带加固

`comfy_submit()` 新增校验：任务带 `source_img` 却缺 `_meta.mode` 时**显式报错**，不再静默降级为 txt2img。

> 背景：验收过程中我自己的测试脚本把参数放在任务对象顶层（而非 `payload` 嵌套），`insert_tasks` 存成了空 payload → `image_mode=False` → 走了 txt2img，**产出了一张人像**。这说明静默降级会产出与产品毫无关系的图且界面无提示。现已改为明确拒绝。

## 五、遗留边界（未变）

1. **Canny 只保可见边界**。丝印、LOGO、刻度、量程、认证标识、透明件**仍必须**走确定性渲染 + 图层回贴（ADR-002）。
   > 实测：CN 强度偏低时，AI 仍会往机身写 "FIVUT" / "Mary Lihao Dosone" 之类的假标识。
2. **产品本体像素建议走真渲染**（ADR-015），AI 只出背景与氛围。
3. **形准 IoU 门槛 0.90 未达标**（四机位平均 0.330）—— 归因于掩膜算法与背景亮度差异，非界面缺陷；判读以人工核对为准。

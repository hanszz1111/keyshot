# 出图链路优化尝试汇总（2026-10-08 ~ 10-09）

> **本文是汇总入口**。记录这两天在千问 Qwen-Image-2.1 与 SDXL 两条链路上**逐项试过什么、得到什么结论**，
> 以及**哪些已采用、哪些走不通**。细节与原始数据在下列专题文档里，本文只做索引与结论。
>
> 数据来源：`outputs/_AB实验/<实验名>/事实卡.json`（每格都记了参数、输入哈希、耗时、解码像素差异）。
> **所有「效应量」都是臂间 MAE 与「同臂换种子」噪声基线的比值** —— 比值越小，说明这个旋钮越没用。

## 一、一句话结论

**采样与调度层面的旋钮几乎都撬不动画面（效应量 0.19–0.29，远小于换种子）；真正有把握的只有两件事 ——
速度（Viggle 6 步快 3 倍、KV cache 快 40%）。而「整体设计的创新度与材质感」这条，
靠换模型 / 换 LoRA / 调参数都走不通，根因在输入侧。**

## 三、逐项明细

### 1–3. 提示词 / 负面词 / CFG（第一轮）

- **CFG=1 时负面提示词完全没有作用** —— 删掉全部负面词后 **4/4 组合逐像素完全相同**。
  原因已查实：`render_defaults.json` 把千问 CFG 固定为 1.0（distilled 模型），
  而 ComfyUI 官方编辑模板说明 **CFG=1 时负面分支不参与生成**。
- **CFG=1.5 时负面词才生效**（4/4 像素不同，MAE 1.69–2.57），代价是**耗时 ×1.7–1.75**（22.1s → 38.2s）。
- ★ **判读陷阱**：C0/C1 的 **文件 SHA256 不同、像素 100% 相同** ——
  ComfyUI 的 `SaveImage` 会把整个提示词写进 PNG 元数据。
  **比文件哈希会得出「有差异」的错误结论，必须比解码后的像素。**

### 4. 文本编码器精度（第二轮）

假设：「项目用 4bit（w4a8），官方模板用 INT8，4bit 削弱了指令跟随」。
做 **2×2 交互对照**（文本编码器 × 提示词，16 格全成功）→
**交互比 2.99 / 3.83 = 0.78（< 1）**，即换 INT8 后提示词作用**没有变大反而略小** → **假设不成立**。

代价实测：文件 +2.83 GiB、front 单张 **+27%**、显存峰值 **95.3%**。

> **后续修正**：目视对比（带**白模真实几何**并排放大）后发现，
> INT8 在镜头环倒角/内圆盘边缘上**更贴近几何**、平坦区斑点更少。
> 所以第二轮否定的只是「INT8 能让提示词更有效」，**没有否定「INT8 画质更好」**。
> ✅ **已按用户决定把默认文本编码器切到 INT8**（改 `render_defaults.json` + `comfy_workflow_qwen21_edit.json` **两处**，
> 只改一处会被另一处覆盖）。

### 5. 采样 shift（第三轮 P2）

本项目工作流**没有** `ModelSamplingAuraFlow` 覆盖节点，用的是 Qwen-Image-2.1 内置的固定 `shift=0.69`；
而**官方每一个 Qwen 模板**都在采样前把它覆盖成 **3.1**。用 ComfyUI 自身代码实跑 25 步 σ：
本项目中段 **0.4278** ／ 官方模板 **0.7706** ／官方 diffusers **0.6650**（中段差 **+80%**）。

**但实测效应只有 0.189** —— 加了极端臂（shift=10 → MAE 7.10）确认补丁确实生效后，
结论是 **σ 的数值差异不能换算成同等量级的画面差异**。→ **保留内置 0.69。**

### 6. Krea-2（另一模型族）

- **通路成立**：官方「风格参考」模板走的其实就是 `ref_latents` 参考图编辑通路
  （`TextEncodeQwenImageEditPlus` → `FluxKontextMultiReferenceLatentMethod("index_timestep_zero")`），
  与 Qwen-Image-Edit 同一套节点。**几何能守住**。
- **但 int8 版不可用**：表面覆盖一层**规则块状/马赛克点阵**，换种子依旧存在 → 是该量化版本本身的问题。
- 速度上无优势：步数 8 vs 25（少 3 倍），但同画幅 992×608 单张 **30.2s vs 30.2–36.5s**，
  被更大的主模型（12.57 vs 6.76 GiB）吃掉。唯一收益是显存峰值略低（92.3% vs 95.3%）。
- 许可：`krea-2-community-license`，非 MIT/Apache。

### 7. Viggle Turbo 6 步 int8 ★ 最强效应

| 臂 | front | 3q4_left | 均值 |
|---|---|---|---|
| 官方 int8 · 25 步（基线） | 23.1 s | 32.1 s | **27.6 s** |
| **Viggle 6 步 int8 · 6 步** | **8.1 s** | **10.1 s** | **9.1 s（快 3.03×）** |
| Viggle 模型 · 25 步（诊断） | 20.1 s | 25.1 s | 22.6 s |

- 显存峰值 **7278 MiB（88.9%）**，低于基线 7805（95.3%）。
- **模型与步数是配套的**：拿 6 步蒸馏模型跑 25 步**反而更差**（块状噪点）。
- ⚠️ **许可是 Qwen RESEARCH LICENSE，明确「FOR NON-COMMERCIAL PURPOSES ONLY」**。

### 8–9. KV cache（第三轮 P3）

- **`QwenImage21Cache(device="cpu")`**：与不插节点**逐像素完全相同**（4/4），
  但**关联机位 42.4 s → 25.4 s（约 −40%）**，单参考的 front 基本不变。**零画质代价 → 建议采用**。
- **`dtype=int8` 不建议**：输出不再相同（MAE 0.28–0.93）且无额外提速。
- ⚠️ **显存峰值没降**（93.4%）→ KV cache 不是占用大头，
  **P3「腾显存以提高 resolution」的前提不成立，它给的是速度不是分辨率空间。**

### 10–12. LoRA 三类来源

- **❌ Qwen-Image-Edit-2511 的 LoRA（跨代）**：装到 Qwen-Image-2.1 上会 **「不报错、不生效」**。
  **决定性证据**：两个**不同**的 2511 LoRA（材质预览 / 多角度）彼此输出 **MAE 0.00、逐像素完全相同** ——
  若都生效绝不可能如此。只看文件名/描述看不出，**必须实测**。
  ★ 生态里 **2511 的 LoRA 远多于 2.1**（连 6.2 万下载的 `fal/…Multiple-Angles` 都是 2511）→ **对我们一律无效**。
- **⚠️ Qwen-Image-2.1 原生（自然曝光）**：**真生效**（MAE 10.4–11.8、改动 18.8–29.8%），
  但改的是影调/曝光，**不改设计**。2.1 原生 LoRA 生态目前**很薄**。
- **⚠️ SDXL 工业设计材质（r64）**：**真生效且强度可控**
  （文生图 基线→@1.0 MAE **21.48**、→@0.6 **11.15**；ControlNet 真实链路 基线→@1.0 MAE **11.39**），
  几何也守得住。**但在项目的 ControlNet 路径上，它主要把中央颜色由橙改成红、蓝环加深 ——
  属材质/色调位移，不是设计创新。**「更好」这件事**未获证明**，待盲评。

## 五、未解决 / 走不通的

1. **★ 「整体设计的创新度」靠换模型 / 换 LoRA / 调参数都走不通。**
   两天里试过的所有外部模型（千问 5 个 + SDXL 1 个 + Viggle 6 步）没有一个能提升设计感。
   → **更可能来自输入侧**：白模/CMF 方案本身的造型、配色、分件，以及设计语言的约束方式。
   **建议单独立项，不要在模型上继续试。**
2. **8GB 显存余量**：峰值长期在 89–95%。KV cache 挪 CPU **不降显存**，Krea-2 也没更好。
   提高 `resolution` 的路**目前堵着**。
3. **许可**：Viggle 6 步（Qwen Research License）、Krea-2（community license）都**非商用**，
   SDXL 工业 LoRA 未标注许可。这三样在商用交付前都需要单独确认。
4. **人工 0–2 分盲评一直没做**：本汇总里所有「画质相当 / 更好 / 更差」都是**我一个人的目视判断**，
   不是评分表，也不算结论。
5. **未跨 SKU**：所有实验都只在 `AI渲染1` 上、2 个机位、2 个种子。

## 七、两条踩过两次的硬规矩

1. **★ 送 `/prompt` 前必须剥掉所有 `_` 前缀键**（`_comment` / `_slots` / `_when` / `_notes`）。
   带着它们会被 ComfyUI 当成节点 → **HTTP 500「Server got itself in trouble」，且不给任何有用报错**。
   生产链路在 `web/server.py:1486-1496` 就是这么做的。
   **2026-10-08（Krea-2）与 10-09（SDXL）各踩一次。**
2. **★ 往 API 工作流插节点不能用 `max(id)+1`**。运行时还会动态加节点
   （本项目关联机位用 `LoadImage(9)`），撞号会导致补丁被覆盖 → **HTTP 400**，
   且症状极具误导：**「front 全成功、3q4_left 全失败」**，容易被误判成"双参考有问题"。
   实验脚本已改为从 **900 起**分配 id。

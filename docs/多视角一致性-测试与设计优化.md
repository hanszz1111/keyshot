# 多视角一致性：测试与设计优化

更新：2026-10-06。目标是让 8 张图首先是**同一 CAD 产品的 8 个机位**，然后才追求 AI 质感。Windows 4060 Ti 8GB 的实际画质、耗时与显存尚未在本轮复测，不能把下面的代码检查当成成图验收。

## 本轮落地：场景图片内容校验

此前场景报告恢复只验证场景签名、路径和 PNG 尺寸。同尺寸图片即使被替换，页面仍可能把它放进“同一场景”一组。本轮把每张保形图的 SHA-256 写入版本 2 场景报告；恢复时逐张重新计算并比对，任一不符就不展示整组。旧版无哈希报告不会自动恢复，**原 PNG 不删除**，重新点击“生成所选视角的保形图”即可生成新报告。离线回归测试覆盖同尺寸内容被改动的情形。

这只保证本地文件未被替换，不评判轮廓、材料归属和视觉质量。千问最终图仍不是保形图；不能把报告哈希解释为 AI 输出一致性得分。

## Windows 真实模型测试矩阵

1. 准备一个有明确前壳、包胶握持、金属按钮和不对称孔位的产品，记录原模型文件哈希。固定材质方案、灯光、8 个机位和输出尺寸。先生成八张保形图；比对每张与同机位白模、对象 ID、深度图的轮廓及相机方向。
2. 逐张人工记 5 项：轮廓/孔位、分模线、部件材质归属、背景洁净、视角正确。通过要求：8/8 机位都正确；任意一张的可见部件错色、错孔或顶底反向都算整组不通过。
3. 在副本中替换一张保形 PNG 为**相同尺寸**的其他图，再刷新网页；整组应不再自动恢复。恢复原图应重新通过。不要在唯一素材上做破坏性测试。
4. 固定种子、候选数 1、同一千问参数，对照“快速配色引导”与“真材质底图”。将每张 AI 图与对应保形图并排检查，记录漂移位置。AI 失败时保留保形组，不用增加步数掩盖结构错误。
5. 记录每机位 Blender/千问耗时、峰值显存、错误文本；先 2 机位再 8 机位。8GB 卡上仍以 CPU 保形渲染为稳定基线，不默认开启新模型或贴图烘焙。

## 下一轮按证据推进

- 若 8 张保形图的同名部件仍有错材质，先检查网格命名、CMF 映射、透明件和背面可见性，再加入“网格 → 材质 → 8 视角可见性”清单；不要先改提示词。
- 若保形图正确而千问图漂移，增加 AI 后验收：与保形图的前景轮廓/孔位/材料区域对照，标记“可交付 / 仅供探索 / 需重做”，而非只看生成成功。阈值必须用 Windows 实图标定，不能凭空指定。
- 若纹理跨面不连续，评估 StableGen 式 UV 烘焙或逐网格 PBR 贴图。该方案工作量和显存需求明显高于当前单色 CMF，先做一个部件的验证样例。

任何实测结果和后续修改均应追加到根目录过程文档，不覆盖旧结论。

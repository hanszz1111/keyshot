## 一、结论

工业产品图的核心不是单纯换更强的生图模型，而是“**相机和结构由 3D 原模型决定，材质与灯光可复用，AI 在受控区域增强观感，所有视角可追溯到同一产品版本**”。推荐先把 Qwen-Image-2.1 从单图精修升级为“目标机位白模主图 + 材质参考图”，再编排多机位任务；高保真主体仍保留 Blender 真渲染和可回贴的遮罩。成图是设计候选，不能代替结构、尺寸、丝印和认证内容的人工验收。

## 三、现有项目的缺口

1. `config/comfy_workflow_qwen21_edit.json` 目前只接 `images.image_1`；`web/server.py` 仅上传这一张图。CMF 预设主要进入文字提示词，个人材质包的照片／PBR 图没有进入千问图像条件。
2. `web/app.js` 在千问模式锁住视角、候选张数和补结构图按钮，且每次只建当前机位的一张任务。必须先打通“选机位 → 补该机位白模 → 使用该机位输入出图”。v3.9 已有局部 ROI 裁剪与确定性合成，不得重复新建一套局部重绘链路。
3. 结构图校验已有文件、尺寸和版本检查，但仍缺产品主体非空、占画面比例、裁切、深度前景等视觉检查。Windows 的具体 3/4 故障还需失败样本确认。
4. 结果对照应绑定 SKU、模型指纹、相机参数、机位、画布、材质版本和任务 ID；宽高相似不能证明像素对齐。
5. 15／30／50 张要变成有计划的设计实验：分组改变 CMF／灯光／种子，具备暂停、续跑、淘汰和精选，而不是重复生成大量近似图。v3.9 已有五套设计语言／布光预设和后端 `apply_design()`，扩展时须复用，不能在前端另拼一份提示词。

## 四、工业产品渲染需要的功能

### 1. 形准与工艺可信度

- 默认锁定外轮廓、孔位、窗口、按键数量、接口、分模线、透明件、螺丝和关键倒角；允许用户明确解除某一约束。
- LOGO、铭牌、刻度、量程、认证与安全警示不交给 AI 猜测；保留原图或矢量层，最后确定性回贴。
- 主体、包胶、金属件、屏幕、透镜、螺丝和印刷层分别指定材质与工艺，避免整机由一个词统一“上色”。
- 纹理记录真实尺度与方向，如拉丝方向、喷砂颗粒、皮纹密度，而不是只写“高级质感”。
- 按激光仪、气体检测仪、测距仪等类别保存重要部件和质检清单。

### 2. 摄影与设计表现

- 摄影棚预设：白底电商、灰底设计稿、深色英雄图、金属工艺特写、透明件透光。每套含灯位、色温、光源面积、背景、地面与阴影。
- 材质与灯光分离；同一 CMF 能切换灯光，同一灯光能对比不同 CMF。
- 固定机位与种子做 3–6 个有明确差异的方案板，比较视觉重心、工艺与色彩。
- 局部修改只作用于选定部件／背景；提供遮罩、边缘羽化、原图回贴与撤销。

### 3. 多视角与交付

- 固定机位：正、背、左右侧、左右前 3/4、顶、底。每个机位单独显示白模／深度／法线／部件遮罩／结果状态。
- 所有视角从各自的 CAD 相机生成输入；不能根据一张正面图想象背面。相同部件的 CMF 应跨视角一致。
- 对照页提供轮廓半透明叠加、局部放大、缺失部件提示和异常文字提醒。自动分数仅供筛选，最终人工确认。
- 任务保存模型指纹、机位、相机参数、材质包版本、灯光、提示词、种子、模型版本与输出路径；支持复刻和只替换单一变量。
- 8GB 显卡串行运行，显示张数、空间和进度；可暂停、续跑、仅重试失败机位。

## 五、建议的主界面

`导入产品 → 检查 3D 模型 → 选视角 → 指定部件材质 → 选灯光 → 预检 → 生成 → 对照 → 收藏／导出`

主页面只保留“产品与视角、材质与灯光、生成设置、预览对照、结果板”五块；采样步数、详细提示词和服务状态放入高级设置。每个禁用按钮必须显示可执行原因，例如“左前 3/4 白模尚未生成 · 点击补齐”。出图量明示“每视角候选 × 视角数 = 总张数”；默认每视角 1–2 张，15／30／50 属高级批量，启动前估算时间与磁盘占用。

### 4060 Ti 8GB 千问试验顺序

1. 固定一件真实产品、一个机位和种子，保留现有单图结果作为基线。
2. 加一张低分辨率材质参考，从现有 768 像素预算试起；记录能否完成、显存、耗时、形准与材质效果。不要直接开启 10 图。
3. 稳定后逐项测试 896／1024、第二机位与连续 10 次运行；一次只变一个因素。
4. 显存不足时明确提示并允许降分辨率／单参考图；不得悄悄切换模型或丢参考图。
5. 若多参考图仍不能可靠保形，优先采用“Blender 真渲染主体 + AI 背景／局部修饰”，不把反复调提示词视为几何保证。

## 七、暂不建议

- 同时引入十种生成模型；先验证现有稳定链路与千问链路。
- 用单张产品照片推断未拍摄的背面和隐藏结构。
- 只用“美观度分数”自动挑图；先过形准、部件和工艺检查。
- 未核对许可证便复制第三方工作流、素材或权重进仓库。

## 八、开工前需要的样本与留痕

需要一份 Windows 上 3/4 不可见的模型及当前白模／深度／报错；一份典型个人材质包以确认是 PBR 贴图、KeyShot 专用包还是材质照片；一组“原模型 + 期望图”，标注必须保持和允许发挥的部位。没有样本可以改流程，但无法证明真实效果达标。

本文件是方案，不是已实现功能。本文档的 GitHub 项目能力来自公开说明，未逐一安装验证。后续每次实现须在根目录过程文档登记，并分别标明“代码已改、自动测试通过、Windows 实机通过、人工质量验收通过”。

## 九、给 Windows 执行 Agent 的操作顺序

**原则：一个阶段一批提交；未过验收门槛，不进入下一阶段。** 本文不要求重装 Qwen／ComfyUI，不下载额外权重，不覆盖现有素材。先做 P0，再做双图材质，再做多视角，最后才考虑真渲染与美术升级。

### 0. 开工和基线确认

1. 在 Windows 的项目根目录先保存当前 `git status`、分支、commit。若有未提交修改或测试数据，不清理、不覆盖；创建本轮独立分支。核对仓库已包含 v3.9 的 `scripts/roi_crop.py`、`scripts/composite_masked.py`、`config/design_presets.json`。若不存在，先同步主线，不能照旧版文件位置盲改。
2. 双击 `一键启动.bat`，在网页确认两套出图模型的状态。用现有一个真实 SKU 记录正面与左右前 3/4 的白模、深度、成图；至少截取一个当前失败状态。三项状态分开记录，不要把“能启动”当成“质量合格”。
3. 在改动前保留当前正常结果和任务数据，不删除旧 `failed` 任务；尤其不要重跑 v3.7 前输入机位曾错配的历史任务。
4. 非 GPU 回归可在 Windows PowerShell 的项目根目录运行：`py -3 web/selftest.py`。若本机 Python 命令不同，用当前项目实际解释器；该自检会启动本地测试服务并清理自己的测试数据。另检查 `web/app.js` 的 JavaScript 语法。记录测试总数和失败项，不能只写“已测试”。

### 1. P0：修通左右前 3/4（最先交付）

**前端 `web/app.js`／`web/index.html`**

- 保留千问的质量档、局部掩膜等尚不支持的围栏，但解除 `viewSelect`、目标视角选择与“补齐所选视角结构图”的不必要禁用。若模型源文件不存在，应单独禁用补图并说明原因。
- 投放区视角矩阵应由 `config/view_presets.json` 的完整可渲染视角生成，不仅遍历已有文件；每格显示“未生成、生成中、已过期、有效、视觉异常”。左、右前 3/4 不得因缺图而从列表消失。
- 千问单张模式先允许明确选一个目标机位。修复后再开放多选；避免一边显示“1 张”、后台却建多条任务。预检错误提供“补齐此机位”操作。

**后端 `web/server.py`／`scripts/blender_pass.py`**

- 将 SKU、源模型签名、机位 key、相机角度、pass 版本、白模相对路径组成可核对的输入记录。千问提交时验证 `source_img` 确属本任务 SKU 与机位，且 `asset_report()` 未判过期。产品原图模式须走单独规则，不强加模型机位。
- `verify_pass_outputs()` 除有效 PNG／同尺寸外，还验白模主体像素占比、透明或背景占比、主体边界是否触边、深度有效像素是否明显为空。阈值先用已知正常／异常样本标定，不在无样本时拍脑袋写死。失败保存诊断缩略图与清楚的中文理由。
- 检查 Blender 机位参数、模型尺度／轴向、相机取景和 clip 范围。正面正常但 3/4 空白时，应能从日志区分“相机未对准、模型转换为空、源图过期、图像有效但主体不可见”。
- 千问预检只依赖千问服务自身及当前任务输入；另一套稳定引擎离线不得无故阻断千问。前端和服务端的可运行判断必须一致。

**P0 验收**：至少 2 个真实模型，其中 1 个为当前失败样本；每个模型的正面、左前 3/4、右前 3/4 都能分别看到白模与深度。三机位各生成 1 张千问候选，任务记录里的机位与 `source_img` 一致；故意删掉／改旧一张 pass，应出现可操作的中文错误，不能静默使用错图。

### 2. P1-A：个人材质包导入和预览

先让用户提供一份真实目录样本，确认它是材质照片、PBR 贴图、KeyShot 特有包，还是混合文件。第一版**只承诺**常见图片参考与 PBR 文件夹；KeyShot 专有格式如无可靠解析能力，显示“暂不支持直接导入”，不假装已转换。

- `config/cmf_presets.json` 继续保存内置预设；个人材质另建清单，记录 `id/name/source_file/hash/base_color/roughness/metallic/normal/texture_scale_mm/direction/preview/assigned_part`。用户导入文件复制到新的受控资产目录，保留原件，不把大图或私人材质上传 GitHub。
- UI 增加“我的材质”卡片：缩略图、材质名、适用部件、贴图缺失提示；支持整机应用和部件覆盖。现有 3D 预览只承诺近似颜色／反射，不把它当最终材质效果。
- 后端严格校验扩展名、文件大小、可解码性和路径边界；无法读取的包给出明确原因，不能让任务在生成阶段才失败。材质方案保存后重新打开网页仍可选。

**P1-A 验收**：一份实际材质包能导入、预览、指定主体与包胶，刷新网页后设置仍在；缺少 roughness／normal 时有清楚降级提示；原文件哈希不变。

### 3. P1-B：Qwen 双图材质试验

- 参考 [官方编辑模板](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_qwen_image_2_1_image_edit.json) 建一个**独立的两图实验工作流版本**，不要直接覆盖已能跑通的单图工作流。`image_1` 固定是目标机位白模或产品原图，`image_2` 是材质参考；API 格式里的 Autogrow 键须按实际节点要求使用扁平点号键，并在提交前校验两张图真的连入工作流。
- 在 `web/server.py` 的 Qwen 分支添加第二图上传与任务元数据：材质文件 hash、工作流版本、两张图的角色。`image_2` 缺失时仍调用原单图流程。多图提示词明确“`<image1>` 决定几何、构图和部件；`<image2>` 仅提供表面材料、颜色与纹理，不复制参考物体形状”。现有 `apply_design()` 仍是唯一设计语言合并点，不在前端重复拼装。
- 先固定 1 件产品、1 机位、1 种子、768 像素预算，做单图／双图成对比较；再逐项试 896、1024 与另一机位。记录显存峰值、耗时、失败率、材质迁移和结构破坏。不得因官方支持更多参考图，就在 8GB 机器上默认开放 10 图。

**P1-B 验收**：双图链路连续 10 次无显存溢出，材质变化肉眼可见且关键孔位／按键未明显恶化；若不达标，保留单图默认并在 UI 标明“双图实验”，继续使用 Blender 真材质路线。

### 4. P1-C：多视角与数量控制

- 每个目标机位必须拥有自己的白模输入和相机记录。前端“选视角／每视角候选数／总张数”三处显示一致；后端入队数和任务元数据必须与预检一致。
- 将千问批次推进到后端持久队列，保存待办、运行中、已完成、失败状态；网页关闭后仍可读取状态，并支持暂停／继续。现有前端顺序提交逻辑可供单张任务保留，不能把它误称为无人值守批量。
- 第一档只开放正面 + 左右前 3/4 三机位，每视角 1 或 2 张。全部串行；单机位失败只重跑该机位。15／30／50 张继续作为高级选择，只有在后端持久队列、取消与续跑验证后开放给千问。
- 输出按 SKU／模型版本／机位／方案 ID 组织；对照页只允许同 SKU、同机位、同模型签名的图叠加。材质与灯光方案可一键应用全部机位，但提示词不得让 AI 推断模型隐藏面。

**P1-C 验收**：三机位 × 2 张准确生成 6 个任务和 6 张图；关闭网页再打开可恢复状态；一机位失败不污染其它结果，重试后不重复创建已成功产物。

### 5. P2：形准与美感升级

先复用 v3.8 的 ROI／掩膜外逐像素不变链路和 v3.9 的五套设计语言。下一步才考虑：Blender 主体真材质、局部 AI 润色、确定性标识回贴、摄影棚参数化、同机位轮廓对照。真渲染与 AI 图要在结果卡标出来源，不能混称“原模型精确渲染”。

**P2 验收**：对至少 3 个不同类别产品，用固定对照表分别评价结构准确、材质可信、工艺细节、灯光美感和操作耗时。任何关键孔位、按钮数、丝印或认证内容错误均判为“不合格候选”，不因整体美观而放行。

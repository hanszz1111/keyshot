# 工业产品材质真实感提升：模型站调研与执行大纲

> 2026-10-09；依据 `main@a24c8b0` 的代码与已入仓 Windows 测试记录。**这是待执行方案，不是新模型已安装、效果已提升或八视图已验收的声明。** 本轮目标是材质/工艺可信度与摄影真实感；现有画幅清晰度已够用，不以放大、锐化或更多采样步数作为主要收益。私有原图和权重不上传公开仓库。

## 1. 当前判断：先修输入与 CMF 链，再比较模型

1. [`出图链路优化尝试汇总`](出图链路优化尝试汇总-20261009.md)记录：Qwen 2511 LoRA 放到 2.1 上逐像素不生效；Qwen 2.1 原生曝光 LoRA 与 SDXL 工业 LoRA 虽生效，却主要改变影调/色调。MAE 只能证明输出不同，不能证明材质更真实。
2. 最新[`提示词实验`](AB实验-千问提示词与CFG首轮记录-20261008.md)中，设计语言写法产生大幅像素变化，但 `AI渲染1` 的 CMF 方案部位在各机位实际不可见，变亮区域约 88% 是背景。**不能把这轮颜色变化写成金属/CMF 提升。**
3. [`E0 记录`](E0-执行记录-基线与测试资产-20261009.md)仍将同一 SKU 的多版本模型/结构图、测试资产追溯与服务稳定列为前置阻断。`AI渲染1` 必须先选定唯一权威 `.3dm`，重出目标机位 pass/底图，重建 CMF 指派并验证部位可见；在此之前不对它做材质模型 A/B。
4. 代码层面还有一个更直接的质感缺口：`config/cmf_presets.json` 已写入 `texture.kind/scale/direction` 和工艺说明，但 `scripts/blender_pass.py::apply_product_cmf()` 当前仅将颜色、金属度、粗糙度（透明件另加透射）接到 Principled BSDF；细砂纹、颗粒橡胶、定向拉丝等元数据**尚未成为可见表面纹理**。`render_product_base()` 用固定三点灯、透明渲染后合成纯色背景；需核验反射与接触阴影是否足以表现真实产品。

**因此实施优先级是：权威几何/CMF 可见性 → 可追溯 PBR 材质底图 → 局部 AI 质感精修 → 候选模型或远程重布光。** 不将模型页样张视为本项目实测。

## 3. 可实施的渲染链（先确定性，后生成式）

### P0｜修复权威模型与部件可见性

- Windows 侧确定 `AI渲染1` 的唯一权威 `.3dm` 版本；从该文件一次性重建八个目标机位的 clay/depth/normal/object ID/PBR 与 manifest。历史资产保留但不得混入新评估集。
- CMF 校验除“部件名存在于 `objectid_map`”外，还需用当前机位 `objectid.png` 验证**至少有目标部件的非零可见像素**；指定部件不可见要给出明确提示，不能静默生图。不可见的背面部件只在对应可见机位校验，不强迫每个部件在每一面出现。
- 对每张 PBR 保存模型指纹、机位/相机、CMF 方案和预设库哈希；上述任一变化都使旧缓存失效。待 [`E0`](E0-执行记录-基线与测试资产-20261009.md) 出口条件满足，再进入效果 A/B。

### P1｜把材质库元数据落实为真实 PBR

- 在 `scripts/blender_pass.py` 对现有 `texture.kind/scale/direction` 建立可审计映射：细砂纹 ABS/TPE 用低幅度、尺度固定的微法线或粗糙度变化；拉丝铝/钢沿明确的物体或 UV 方向做各向异性反射；喷砂金属用细且各向同性的粗糙度变化。纹理坐标固定在模型上，**不能因相机换位而游走**。
- 按工艺分配反射范围：塑料与橡胶不能共享同一高光；金属表现来自正确反射环境而非单纯变亮/加银色。优先保留分模线、倒角与材质边界；微纹理不生成新的几何线条。
- 底图灯光提供可选“中性检验”“柔光棚拍”“金属反光卡”三档，光位/能量/色温随八视角**同一方案**复用；地面/接触阴影单独出层，避免脏背景和伪悬浮。评估 Standard 色彩变换是否使亮金属高光截断，任何更改先做同图 A/B。
- 先在塑料+橡胶、塑料+金属、透明+金属三种真实样本上做材质球及产品局部放大对照。性能不得让八面批量在 8GB 上频繁 OOM。

### P2｜部件级 AI 精修，而非全图自由重绘

- 使用当前机位 object ID 生成严格选区；Qwen 2.1 只增强目标部件的表面/反光，结果以原 PBR 底图为基准拼回。掩膜外**解码像素逐像素相同**，分模线与孔位周围设保护区并人工检查边缘接缝。
- 输入提示词由 `CMF 方案 → 部件名/材质/颜色/工艺 → 当前机位可见区域 → 光照` 生成。提示词负责描述与审计，**材质所属关系以 ID 掩膜和 PBR 为准**；不能只靠文字保证位置。
- Qwen 默认 CFG=1 时负面提示词已被实测为零作用：把必要的保形与禁增件要求写成短而明确的正向编辑约束，不继续堆长负面词。设计语言型提示词先检查指定部件是否实际可见，再看材质变化；不得用背景变化代替质感得分。

### P3｜外部候选只作隔离 A/B

- 同一 PBR 底图、同一机位、相同提示目标和参考图，分别测试当前 Qwen、候选 FLUX 工业材质、Kontext 重布光；先单张烟测结构和峰值显存/费用，再扩至八面。**不同底模不能宣称是严格单变量模型内对照**，只能作整链方案比较。
- 候选即使单张“更高级”，只要分模线、孔位或跨视角 CMF 明显倒退，不能加入默认模型菜单。FLUX/Kontext 的在线样张和第三方作者自述只作筛选依据；若本地 8GB 超负荷，保留为可选远程实验，不挤占生产实例。

## 4. 评分、停止条件与交付

| 维度 | 具体看什么 | 硬失败例 |
|---|---|---|
| 结构与机位 | 轮廓、孔/按键、分模线、正俯仰角和左右 3/4 | 少件/多件、孔位偏移、视角错位 |
| 材质可辨识度 | ABS、TPE、拉丝/喷砂金属是否在放大与正常浏览尺度均能区分 | 橡胶变亮金属、跨分区串色 |
| 工艺真实感 | 微纹理尺度、拉丝方向、倒角/接缝处反射连续 | 纹理随相机游走、凭空出现划痕/装饰线 |
| 摄影真实感 | 反光板形状、亮暗过渡、接触阴影、背景洁净 | 产品悬浮、脏背景、金属高光大片死白 |
| 八面一致性 | 同一部件颜色、材质、纹理方向和结构在各面连续 | 一面塑料一面金属、前后形体不同 |

先用 **3 个 SKU × 正面/左前 3/4/仰视 × 2 种子**筛方案，再扩到每 SKU 八面；至少两人不知候选名称地逐项打分。记录输入/模型/工作流哈希、提示词、机位、分区、耗时、显存和失败原因。MAE 只作为“是否生效”诊断，不作为美感分数。**晋级顺序：结构硬失败不增加 → 部件 CMF 与八面一致 → 材质/摄影盲评改善 → 时间与显存可接受。** 未达标继续使用现有路径，不宣称升级成功。

### P0（部分完成）｜可见性校验已补上

**做了什么**：两处配合的改动。

1. **`scripts/blender_pass.py`**：新增 `visible_object_ids(png_path)`，在写完 `objectid.png`
   之后**反解出「本机位实际出现的部件号」**并写进 `pass_manifest.json` 的新字段 `visible_object_ids`。
   存储时 ID 被除以 65535 压进 16 位 PNG，读回乘 65535 还原；抽样 `step=2` 个像素即可判定"是否出现"。

     **交集为空 → 直接报错**（提示"先核对方案与结构图是否来自同一个模型版本"）；
     **部分不可见 → 不判死**，但把不可见部位名写进 `meta["cmf_parts_not_visible"]` 供审计。

| 用该清单复演校验 | ✅ `AI渲染1` 的 4 个方案部位 → id **20 / 1737 / 1742**，与可见集合**交集为空** → **会报错** |

### P1（核心部分完成）｜材质库元数据已落实为真实 PBR

**问题**（原方案 §1.4 的判断，已复核确认）：`config/cmf_presets.json` 有 14 条预设，
每条都写了 `texture.kind/scale/direction` 与工艺说明，但
`scripts/blender_pass.py::apply_product_cmf()` **只把 `Base Color`/`Metallic`/`Roughness`
（透明件另加 `Transmission`）接到 Principled BSDF，一个纹理节点都没有** ——
也就是说细砂纹、颗粒橡胶、定向拉丝这些元数据**从来没有变成可见的表面纹理**。

**做了什么**：新增 `_apply_surface_texture(mat, bsdf, preset)`，把 9 种 `kind` 落成程序纹理：

| kind | 节点 | bump 强度 | 附加 |
|---|---|---|---|
| `fine_grain` | Noise | 0.05 | — |
| `sandblast` | Noise（更高频） | 0.09 | — |
| `satin` | Noise | 0.03 | 各向异性 0.35 |
| **`brushed`** | **Wave（BANDS，沿物体 X）** | **0.10** | **各向异性 0.85** |
| `pebbled` | Voronoi F1 | 0.22 | — |
| `leather_grain` | Voronoi F1 | 0.26 | — |
| `wood_grain` | Wave（RINGS） | 0.14 | — |
| `woven` | Wave（BANDS） | 0.16 | — |
| `smooth` / `scale=none` | **不建节点** | — | — |

**两个刻意的设计约束**：

1. ★ **纹理坐标用 `Texture Coordinate` 的 `Object` 输出**，不用 `Generated`/`Window` ——
   后者随相机与取景变化，会让同一部件在不同机位纹理尺度/方向不一致（"纹理游走"）。
   这是原方案 P1 明确要求的一条。
2. **幅度刻意做小**（0.03–0.26）。微纹理是"让高光产生变化"，不是"画图案"；
   过强会在倒角/分模线上生成原模型不存在的视觉线条。**只改材质节点，不新增几何。**

**验证**（Blender 4.5.0，`渲染3 / back`，同机位同相机）：

| 渲染 | 日志 | 与改造前底图的差异 |
|---|---|---|
| 细砂纹 ABS | `fine_grain/fine/isotropic bump=0.05` | MAE 2.41 ｜ 最大差 236 ｜ 改动>8 的像素 2.2% |
| **拉丝阳极铝** | **`brushed/fine/longitudinal bump=0.10 各向异性=0.85`** | MAE 3.73 ｜ 最大差 238 ｜ 改动>8 的像素 4.3% |

目视（`outputs/_P1验证/P1纹理对比.png`）：
- **① 改造前**：表面**完全均匀**，两个圆凹是平盘，纯塑料感；
- **② 细砂纹 ABS**：高光碎化成**细颗粒**，凹口边缘更有定义；
- **③ 拉丝阳极铝**：**方向性金属高光**明显，凹口读作抛光金属杯，与 ① 是**两种材质**的观感。

★ **这是确定性的真实 PBR，不是 AI 生成的** —— 说明「材质感不够」这条
**可以在渲染器层面直接解决**，不必依赖模型或 LoRA。

**未做**：三档灯光方案（中性/柔光棚拍/金属反光卡）与接触阴影分层（原方案 P1 的其余部分）；
材质球对照；`Standard` 色彩变换下亮金属高光是否截断的核对。

### 发现的一条缓存缺陷（建议一并修）

`product_base_spec()` 的文件名摘要是
`sha256({algorithm, scene_id, view, manifest_mtime_ns, camera, resolution})[:16]` ——
**不含渲染器/代码版本**。
→ 像本轮这样改了材质节点后重新渲染，**文件名不变、会直接覆盖旧底图**，
没有"代码变了让缓存失效"的机制。原方案 P0 要求"上述任一变化都使旧缓存失效"，
建议把 `blender_pass.py` 的版本（或材质映射表的哈希）加进摘要。
**本轮验证时我是手动输出到 `outputs/_P1验证/` 才避开了覆盖。**

# 工业材质增强：底层架构与 Windows 实施报告

> 日期：2026-10-10；代码基线 `main@8cfc998`。本报告是开发任务书，接口、目录与示例均须按“现有/拟新增”标记理解。目标机器 RTX 4060 Ti 8GB、32GB 内存。目标优先级：材质相似度、立体光影、部件归属、八面一致性；降噪与放大不是本轮主目标。本文没有宣称新模型已运行通过。

## 1. 已核对的现状与必须更正的前提

- 现有 `web/server.py` 负责任务与 HTTP 接口；`scripts/blender_pass.py` 负责导模、相机、结构 pass、程序材质与产品底图；`config/cmf_presets.json` 管理 CMF 预设；`scripts/cmf_guide.py` 生成确定性配色引导。
- 已有 `validate_cmf_pass_contract()`，供 CMF 与底图路径检查同源/可见性；已有全像素 `visible_object_id_stats()`。这些属于已提交实现，仍需按本报告测试其端到端行为。
- **撤回旧前提：**Windows 最新记录证明 32 个 `.3dm` 文件内容哈希相同，已指派的四个部件可见。此前“模型版本错配”“部件全不可见”“88% 改动在背景”不再作为修复依据。详见[更正记录](更正记录-PIL位深误导导致的两处错误结论-20261010.md)。不能再要求用户从相同内容中挑版本。
- 16 位 RGBA PNG 的 ID 不能经普通 Pillow 转灰度后归因。审计、选区、CMF 引导与质量评估都必须使用验证过的完整 16 位读取路径。普通彩色图片仍可正常使用 Pillow。
- 不同机位的“变亮像素百分比”受可见面积和光照影响，**不能单独证明材质不一致**。应比较同一物理部件、可见面积归一化后的指标及八面目视；未指派网格走主体材质，也不等于材质缺失。
- 当前着色器已有程序纹理，但没有完整的外部 PBR 材质包接入；底图签名仍未纳入材质着色代码内容。后两项是本轮优先开发内容。

## 2. 技术路线及免费资源

主流程：**材质来源 → 标准材质包 → 部件绑定 → 冻结场景 → Blender 八面 → 可选局部 AI 精修 → 验收**。材质在模型空间确定一次，相机切换时复用；不让每张 AI 图独立决定材质。

| 资源 | 用途与选型 | 部署决策 |
|---|---|---|
| [Poly Haven](https://polyhaven.com/license)、[ambientCG](https://docs.ambientcg.com/license/) | CC0 的 PBR 贴图、HDRI；先挑干净金属/塑料表面，避免默认锈蚀旧化 | 首轮基准材质，手工下载选定资源包并登记来源，不抓取整个站点 |
| [Material Maker](https://www.materialmaker.org/) | 免费程序材质编辑与 PBR 导出；纹理方向/尺度可调 | 可离线预制材料；社区资产逐项记录许可 |
| [StableMaterials](https://huggingface.co/gvecchio/StableMaterials) | 文字或材料局部图片生成 Basecolor/Normal/Height/Roughness/Metallic；基础 512、标准与 LCM 模式；OpenRAIL | 首个 AI 材质候选。8GB 尚未实测；独立进程运行，完成后卸载再启 Blender/Qwen |
| [Chord 权重](https://huggingface.co/Ubisoft/ubisoft-laforge-chord)、[官方节点](https://github.com/ubisoft/ComfyUI-Chord) | 图片到 PBR 材质估计；需接受 Research-Only-Copyleft 条件 | 第二阶段个人研究候选；仅在 StableMaterials/现成材质不足时试，显存待测 |
| [IC-Light](https://github.com/lllyasviel/IC-Light) | 重布光，增强体积和主次反光 | 后期单图实验；不承担八面材质归属 |
| [Qwen 2.1 Union](https://huggingface.co/alibaba-pai/Qwen-Image-2.1-Fun-Controlnet-Union)、[INT8 包装](https://huggingface.co/Comfy-Org/Qwen-Image-2.1/tree/main/model_patches) | 深度/线稿/掩膜控制；INT8 控制权重约 3.78GB，额外叠加主模型 | 8GB 压力需烟测，不能以文件大小代替峰值显存 |
| [MaterialMVP](https://github.com/ZebinHe/MaterialMVP)、[Hunyuan3D 2.1](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1) | 网格与参考图驱动多视角 PBR | 长期路线；官方 Hunyuan 纹理生成约 21GB 显存，不列入本机第一阶段 |

下载权重免费不等于云端运行免费。模型输出的粗糙度/金属度是估计值，应允许人工修正；没有测量样本时不能承诺物理参数与实物完全一致。

                 ↓ HTTP

web/render_contract.py                 冻结模型/材质/相机/灯光/版本

                 ↓ 文件化请求/响应

避免一次拆完 `server.py`：先抽纯数据校验/签名，再接现有函数。主服务保持标准库运行；torch、diffusers、图像重依赖只在 worker 环境。Blender 材质节点代码只由 Blender 解释器导入。

现有 `POST /api/ui/product/batch` 继续工作；`product_base_spec()` 内调用新场景契约并沿用现有任务状态和图像展示组件。新增 API 是提案，开发后必须更新接口说明：

| 接口 | 请求/返回关键字段 | 行为 |
|---|---|---|
| `POST /api/ui/materials/import` | 上传文件或预登记本地上传 ID → `material_id, revision, warnings` | 不接收任意系统路径；解压限制文件数量/尺寸，拒绝越界路径 |
| `GET /api/ui/materials` | 筛选类别 → 材质列表/预览/来源 | 只返回可验证材质 |
| `POST /api/ui/materials/generate` | `backend, prompt, reference_id, seed, mode` → `job_id` | 后台生成，立即返回 |
| `GET /api/ui/material-jobs/{id}` | → 状态、阶段、真实进度、耗时 | 无内部采样进度时只显示阶段和已用时间 |
| `POST /api/ui/material-jobs/{id}/cancel` | → 取消结果 | 清理临时任务，不删除已验收材料 |
| `POST /api/ui/cmf/material-bindings` | `sku, scheme_version, part_names, material_id, revision, mapping` | 批量原子绑定；版本冲突返回 409 |

错误码至少包括 `INVALID_MAP`、`ID_PRECISION_LOSS`、`STALE_CONTRACT`、`MATERIAL_REVISION_MISSING`、`GPU_BUSY`、`OUT_OF_MEMORY`。前端转换成中文操作提示，日志保留完整诊断。

## 4. 核心数据格式

每个材质 revision 不可变；修改参数产生新 revision。路径相对材质包根目录，文件哈希必须与实际文件一致。以下是拟议 schema v1 示例，不是仓库已有配置：

```json
{
  "schema_version": 1,
  "material_id": "abs-fine-matte",
  "revision": "content-sha256",
  "name": "细砂纹 ABS",
  "source": {"kind": "imported", "url": "作者资源页", "license": "CC0"},
  "maps": {
    "basecolor": {"file": "basecolor.png", "space": "sRGB", "sha256": "..."},
    "normal": {"file": "normal.png", "space": "Non-Color", "convention": "OpenGL", "sha256": "..."},
    "roughness": {"file": "roughness.png", "space": "Non-Color", "sha256": "..."}
  },
  "surface": {"metallic": 0.0, "roughness_multiplier": 1.0, "normal_strength": 0.25},
  "mapping": {"mode": "object", "tile_size_mm": [10, 10], "rotation_deg": 0},
  "color_policy": "cmf_tint"
}
```

规则：非金属未提供 metallic map 时使用明确的 0；metallic/roughness 缺图用标量，不从灰度亮度猜金属。`cmf_tint` 仅对合适的中性色材质使用，木纹/织物等可保留 `source_color`。ORM 等打包贴图须显式指定通道，不靠文件名猜。

CMF 旧字段 `cmf/color/label` 保留；新增 `material_ref: {id, revision}` 与部件级 mapping override。存储键仍沿用稳定网格名与模型指纹，屏幕 ID 只用于投影；未来若升级稳定部件 UUID，另做迁移，不能同时打乱当前选区映射。

场景契约至少冻结：模型内容哈希、导入器版本、源单位、CMF 方案 revision、所有材料 revision、映射尺度/方向、灯光/HDRI 内容哈希、背景、渲染器代码哈希、Blender 版本、八机位相机和尺寸。规范化 JSON 后 SHA-256 得到 `scene_id`；每张图再结合 view 得到产物键。相同模型不同文件名不能单凭名称判不同产品。

## 5. 材质导入与 Blender 节点实现

1. 材料写入暂存目录，验证格式、尺寸、通道、颜色空间和路径；生成 manifest 与预览球，通过后原子移入材料库。库置于可配置私有目录（建议 F 盘），公开 Git 仅含 schema/测试小图，不含用户材料包。
2. 读取 Basecolor 为 sRGB；Normal/Roughness/Metallic/Height 为 Non-Color。Normal 经 `ShaderNodeNormalMap`；Height 以低幅 Bump 可选叠加，默认不做真实位移，避免改动外轮廓。DirectX 法线明确翻转绿通道，禁止默默当 OpenGL。
3. 统一 CAD 单位到毫米或米并记录换算，使用 `tile_size_mm` 控制纹理大小。Object 坐标须经单位与对象变换校准；不能所有 CAD 都固定频率 240。UV/对象坐标都可跨相机稳定，Generated 并非天然随相机变化；Window 坐标才不适合固定材质。
4. 拉丝方向必须有可选轴/UV 切线，且 Bump 条纹与各向异性切线一致。平行拉丝和圆环拉丝分开预设。多网格共用材料但方向不同，应各用正确映射输入，不靠全局 X 轴。
5. 材质 shader 输出同一个 Principled BSDF；镜面、透明、清漆需独立参数，先保留现有真渲染限制。材质预览球与产品共用节点构建器，避免预览好看、实图另一套参数。
6. 三档灯光：中性检验、柔光棚拍、金属条形反射。每个批次冻结同一套世界空间光源；相机旋转可造成合理的高光变化，不强求八面亮度相同。阴影使用独立层/明确地面策略，避免遮挡仰视。

## 6. StableMaterials 独立 worker 的具体落地

先安装在新环境，不修改当前 8188/8190 的依赖。Windows PowerShell 在项目根运行以下准备步骤（路径可配置）：

```powershell
$MaterialRoot = 'F:\AI-Renderer\material-lab'
New-Item -ItemType Directory -Force $MaterialRoot
py -3.10 -m venv "$MaterialRoot\venv"
$MaterialPython = "$MaterialRoot\venv\Scripts\python.exe"
& $MaterialPython -m pip install --upgrade pip
```

后续依赖安装由执行端先核对作者模型卡与本机驱动，再生成 `requirements-materials.lock.txt`（拟新增）并按锁文件安装。不要在报告中硬写未经本机验证的 torch/CUDA 组合。下载 `gvecchio/StableMaterials` 时固定 Hugging Face commit revision、记录 SHA-256；先审其自定义 `pipeline.py`，作者用法需要 `trust_remote_code=True`，只对固定审阅版本启用。

worker 的核心调用按作者模型卡实现：

```python
# 拟新增 worker 内的最小核心；依赖与输入校验省略，非现有程序代码
pipe = DiffusionPipeline.from_pretrained(
    local_snapshot, trust_remote_code=True,
    torch_dtype=torch.float16, local_files_only=True)
pipe = pipe.to("cuda")
material = pipe(
    prompt=material_prompt, tileable=True,
    guidance_scale=10.0, num_images_per_prompt=1,
    num_inference_steps=50,
    generator=torch.Generator("cuda").manual_seed(seed)
).images[0]
# 导出 material.basecolor/normal/height/roughness/metallic，再交给材质包校验
```

上述 50 步/CFG 10 来自作者标准示例，仅作烟测起点。LCM 模式须同时换 `unet_lcm` 和 `LCMScheduler` 才使用作者 4 步配置，不能只把标准模型改成 4 步。首轮只生成单张 512 材质；不与 Qwen/Blender GPU 并驻。8GB OOM 则记录并退出，之后再单独验证卸载方案，不循环重试到系统失去响应。生成一次的材质包可供所有视角复用，不必每张产品图重新运行材质模型。

worker 采用 `--request <absolute.json> --output <absolute-directory>` 契约；请求含 `job_id/backend/model_revision/prompt/reference/seed/mode`。只允许指定输出目录；进度 JSONL 写 `loading/generating/validating/ready/failed`，stderr 为诊断日志。结果返回五类贴图与来源信息，主进程负责入库，不让 worker 直接改 CMF 方案。

## 7. 调度、缓存与前端操作

- 材质生成、Blender GPU、Qwen 任务共用 GPU 排他租约；CPU 渲染也需遵守现有 Blender 通道限制。状态机：`queued → running → validating → ready`，失败/取消独立终态。重启后将遗留 running 标为 interrupted，保留日志。
- 发布前重新验证场景签名；渲染中换材料或脚本，临时产物不进入当前系列。旧图保留供比较，缓存只命中同签名产物。八面缺一张时标“未完成”，不得混入上一版补齐。
- 前端保持四步：选择模型 → 选择部件 → 选材料/调整纹理尺度与方向 → 选择灯光并出八面。高级参数默认折叠；显示“程序材质/导入材质/AI 生成材质”和版本，便于用户理解来源。
- 选区覆盖色与最终材质色分别表示：选区高亮用于定位，右侧同时显示材料球、颜色、工艺标签；取消高亮仍能看到真实材质预览。支持多部件批量绑定及撤销。
- 进度条展示已完成机位数、已用时间、按近期同类任务估计的剩余时间；未获得采样步回调时不伪造单张百分比。结果点击看原尺寸，并列显示基准/结果、材料名称、同系列八面缩略图。

现有回归入口：`python -m unittest web.test_product_base`；图像相关测试使用已有具备 numpy/Pillow 的解释器运行 `web.test_cmf_guide`。新增测试建议 `test_material_package.py`、`test_render_contract.py`、`test_material_jobs.py`；测试真实失败模式，不仅复述实现。`web/selftest.py` 涉及测试任务和素材，放隔离测试目录运行并记录环境。

交付事实卡记录：代码/模型/材料 revision、场景契约、全部机位、输出像素哈希、耗时/显存、失败例、盲评分与回退选择。未看见私有实图的复审端只签收代码和方法，不代签视觉质量。每阶段更新 `AI/RESULT` 对应轮次及根过程文档；第一版完成 M0–M4 即可评估实用性，无需等待所有候选模型都接入。

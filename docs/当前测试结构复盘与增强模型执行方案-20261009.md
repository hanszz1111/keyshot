# 当前测试结构复盘与增强模型执行方案

> 日期：2026-10-09。基线 `main@407cc22`。本文是 **Windows 4060 Ti 8GB 的下一轮执行任务书**，不是新模型已通过验收的声明。只依据已入仓代码、Windows 实测文字与作者模型页；`outputs/` 中的原始图和事实卡未入 Git，本机 Mac 无法复核图像质量。

## 1. 结论先行

现在的自动测试擅长防止**参数混杂、错机位深度图、PBR 缓存污染和前后端流程回归**，但画质证据仍停在 **1 个 SKU、正面与左前 3/4、2 个种子、单人目视**。像素 MAE 说明“改动大小”，不说明“更好”。因此下一轮不要再并行加许多 LoRA：先把**跨 SKU × 八面 × 部件级评分**补齐，再选与 Qwen 2.1 同代的结构控制模型做单变量比较。造型创新与分件工艺更可能需要改白模/PBR/CMF 输入，而非期待风格 LoRA 自动发明一个更好的产品。

## 3. 关键缺口与优先级

1. **P0｜测试样本太窄。** 现有 1 SKU/2 机位/2 种子不能回答背面、俯视、仰视和多材质跨视角一致性。先扩大评估集，不先调更多旋钮。
2. **P0｜没有质量判据闭环。** MAE 与种子噪声比只能筛“是否真的生效”。应补轮廓/孔位/分模线/部件颜色与材质的**分区指标 + 双人盲评**；失败图必须留在私有目录供复盘。
3. **P1｜输入侧比较仍未完成。** `input` 预设已有 `CMF guide` vs `PBR product_base` 两臂，但[汇总](出图链路优化尝试汇总-20261009.md)未给跨 SKU 结果。先验证 PBR 保形底图，不要跳到新模型。
4. **P1｜局部编辑只有插件就绪。** `InpaintCropImproved/InpaintStitchImproved` 已在隔离 8190 注册，尚无 Qwen ROI 端到端及掩膜外不变证据；UI 不能标成已完成。
5. **P2｜同代结构模型值得试。** [Alibaba PAI Qwen-Image-2.1 Fun ControlNet Union](https://huggingface.co/alibaba-pai/Qwen-Image-2.1-Fun-Controlnet-Union)支持 Depth、Canny、Lineart 和掩膜，是直接对应结构问题的候选；[Comfy-Org](https://huggingface.co/Comfy-Org/Qwen-Image-2.1/tree/main/model_patches)提供 INT8 包装权重。它额外叠在底模上，不是换一张 LoRA，**8GB 能否装载与现有 API 编辑链是否可接，都未验证**。
6. **P3｜跨代模型只作独立研究。** [fal 多视角 LoRA](https://huggingface.co/fal/Qwen-Image-Edit-2511-Multiple-Angles-LoRA)依赖 Qwen-Image-Edit-2511，不能放进当前 Qwen 2.1；本项目已有两个 2511 LoRA 在 2.1 上逐像素相同的静默失效证据。不要再按“文件能加载”判断兼容。

## 4. 分阶段执行（Windows agent 按序做，每阶段独立提交）

### E0｜锁定基线与测试资产（先做，无需新模型）

- 保留 8188 正式实例、8190 Qwen 实验实例、现有生产权重及回退配置；记录 `git rev-parse HEAD`、ComfyUI 版本、实际 `render_defaults.json` 与 API workflow 权重名称、各权重 SHA-256。当前默认文本编码器是 INT8，**不得误用旧文档的 W4A8 默认叙述**。
- 建立私有评估集：**3 个不同 SKU × 八机位 × 2 种子**。SKU 应覆盖硬边/孔/分模线、多曲面、三材质/透明件；八机位至少正、后、左、右、左前 3/4、右前 3/4、俯、仰，机位命名与 `config/view_presets.json` 映射对齐。每个机位导出同一相机的 clay/depth/normal/object ID/PBR 与 manifest；失败机位先修 CAD 导入/相机，不能让 AI 猜缺失面。
- 不上传私有产品原图。给每张保存 `sku, view, camera, cmf_version, input_hash, model_hash, workflow_hash, seed, steps, cfg, sampler, cache, GPU峰值, wall_time, error`。已有脚本的 `--plan` 先预览任务；所有实验写 `outputs/_AB实验/<轮次>/`，不污染生产任务库。
- 建盲评表：结构（轮廓、孔位、分模线、部件数）、视角、跨视角 CMF、工艺/美感、背景各 0–2 分；两人独立评分，分歧交第三人。再加硬失败标记：异面错色、少件/多件、孔位明显偏移、俯/仰角不正、产品主体脏污。以八视图 2×4 总览先判是否同一件产品。

**E0 出口：**测试集所有机位的结构 pass 完整且机位绑定；评分表、盲评规则和真实基线图就绪。若不满足，停止模型增强。

### E1｜先验证 PBR 输入与局部编辑（最可能解决产品一致性）

- 用现成 `--preset input` 比 `CMF guide` 与 `product_base`。首轮只选 3 SKU × 正面/左前 3/4/仰视 × 2 种子 × 2 臂，共 **36 张**；控制同一主模型、文本编码器、CFG、步数、采样器与参考图。若一臂明显更稳，再扩八机位。不能把“只换输入”同时变成“换了灯光/机位/目标色”。
- 局部编辑先用 `object_id` 为前壳、握把、装饰件选区；裁切后 Qwen 只编辑目标件，再以现有 `scripts/composite_masked.py` 或已审插件拼回。每 SKU 至少改一处塑料→胶皮或金属表面；**掩膜外合成后像素必须完全不变**，边缘不能有接缝，分模线要连续。掩膜外若经过色彩转换导致误差，拆出那一步单独解释，不放宽成“肉眼差不多”。
- 新增自动测试：三材质 `object_id` 映射、机位错图拒绝、掩膜外逐像素不变、失效掩膜/空掩膜、PBR manifest 变化导致缓存失效、ROI 拼回尺寸不变。UI 只有后端真实通过才解锁选区按钮。

**E1 出口：**相对当前基线，三 SKU 的结构硬失败不增加、至少一项结构/CMF 盲评分稳定提高；否则保留旧输入。局部编辑每个样本都满足掩膜外不变。

### E2｜Qwen 2.1 Union 结构控制：隔离烟测，再 A/B

- 先查看作者模型页、ComfyUI/适配节点当前源码和 8190 `/object_info`。确认 `model_patches` 加载方式与本机 ComfyUI 版本兼容；**不能直接把 Union patch 塞进现有 `TextEncodeQwenImage21` API JSON，就声称已经实现 Depth Control**。记录模型来源、许可、文件大小与 SHA-256。先在隔离环境下载 **INT8 patch**，不动 8188，也不自动安装一串第三方依赖。
- **烟测门槛**：一次一张、640 再 768、正面真实深度图，跟踪 GPU 峰值与是否 OOM；确认可用后再做左前 3/4 与仰视。若 8GB OOM/CPU 换页导致极慢，停止本地部署，记录远程 GPU/API 备选，不强行并发或覆盖生产。
- **受控 A/B**：固定 PBR 输入/提示词/种子，A 无 Union、B Union+同机位 Depth、C Union+同机位 Lineart/Canny；先 3 SKU × 3 难机位 × 2 种子 = **18 个配对格**。Union 强度先按作者建议的 1.0 烟测，再按单变量比较 0.5/0.75/1.0；不能同时改输入或步数。若控制模型仅能走文生图而无法保留现有参考编辑，实验应明确改为“独立结构生成链”，**不要拿不同任务链输出做伪同条件 A/B**。
- 评分除 0–2 人评外，增加前景 silhouette IoU、部件掩膜重叠、关键孔/按键/分模线人工核对；背景 MAE 不参与结构评分。阈值按 E0 基线预注册，不能看完结果再改门槛。

**E2 出口：**在三 SKU 的难机位上结构硬失败数下降、CMF/美感不显著倒退，8GB 无 OOM 且时间可接受，才考虑注册为实验引擎。若只改善边缘却换色/换形，退回 PBR+现有 Qwen。

### E3｜速度/风格/跨代模型（低优先级）

- 将 `QwenImage21Cache(device="cpu")` 在生产工作流中按单变量接入与复测：已有 4/4 像素相同、关联机位约快 40% 的 Windows 证据；**并未节省峰值显存**，不能用它推高分辨率。若同机复测失败即回退。
- Viggle 6 步只做快速预览候选：现有 1 SKU/2 机位/2 种子约 3 倍提速，但仍需完整盲评与当前用途的许可核对；6 步模型与 25 步不可混用。SDXL 工业 LoRA只当影调/材质候选，先做 0.3/0.5/0.7 的小样，不能把色调位移叫“设计创新”。Krea-2 INT8 已出现稳定块状伪影，不重复同版本盲测；若试 FP8，仅在独立探针中做。
- 只有 E0–E2 完成、且仍有“从单图推未知面”的明确需求时，才单列 Qwen-Image-Edit-2511 + 多视角 LoRA 引擎。其生成的未知面不能覆盖 CAD 真相；与当前 Qwen 2.1 的结果须按任务差异标注，不能直接混入相同 A/B。8GB 成本先烟测，失败就转远程，不安装到 8190 当前主实例。

## 5. 验收与交付格式

每阶段提交：①可复现的输入/模型/工作流哈希与参数事实卡；②成功、失败、OOM、耗时、显存表；③按 SKU 的八视图拼图与两人盲评分；④结构/CMF 失败例；⑤ go/no-go 与回退方案；⑥新增自动测试及 Windows 真机运行结果。私有图片仍不入 Git，可发布经用户确认脱敏的小样；若公开仓库只有数值和单人目视，结论必须标“证据不足”。

判定顺序：**结构硬错误为 0 → 同 SKU 八面 CMF 一致 → 双人评分不低于基线 → 时间/显存可接受 → 才讨论视觉惊艳程度。** 任何一项失败，不改默认模型；实验功能在 UI 标“实验”，保留原路径回退。把每轮结论更新到 `AI/RESULT.md`，复审写 `AI/REVIEW.md`，所有修改追加到根目录过程文档；本文件中的 E0–E3 逐项勾销，而不是用“已经下载模型”代替“已通过质量验收”。

# 材质真实感更新审核纠正：Windows 详细执行流程

> 日期：2026-10-09。审核基线 `main@9e6eaa4`，执行结果参见 [`AI/RESULT-R4.md`](../AI/RESULT-R4.md)。本文件是**修复任务书**，不是已完成记录；不擅自确定 `AI渲染1` 的权威 `.3dm` 版本，不覆盖或删除旧资产，不把像素差异等同于画质提升。目标机器：RTX 4060 Ti 8GB / 32GB RAM。原始模型、私有图片、权重仍留在 Windows 本机，不入公开 Git。

## 0. 先给执行方的结论

当前代码已把 9 类程序纹理接到 Blender，也新增了可见部件名单，但**尚不能称为 CMF/八面质感闭环**：旧 `pass_manifest.json` 没有可见名单会绕过新校验；`product_base_spec()` 仍只按部件名检查并可能接纳不同模型版本的结构图；材质脚本变化不进入 PBR 缓存标识；可见 ID 每隔一个像素抽样且读取失败写 `[]`，会把“读取失败”和“确实没有部件”混为一谈。`AI渲染1` 的权威模型与十机位资产仍未重建；R4 的质感结论只来自单产品、单机位、单人目视。

**推荐按 S0 → S1 → S2 → S3 → S4 的顺序分别提交。** S0 的基线锁定先完成；若用户尚未选定权威模型，S1–S3 可以用测试夹具继续，但 S4 必须等待该选择。各阶段代码验收未通过不得推广至正式出图。正式 Qwen/SDXL 实例、模型权重与默认提示词不在本轮修改范围。

| 阶段 | 目的 | 交付 | 出口条件 |
|---|---|---|---|
| S0 | 锁住现状并备选权威源 | 基线清单、候选 `.3dm` 的哈希/预览、用户选择记录 | 旧图保留且不混用；权威模型未选时标为 S4 阻断 |
| S1 | CMF 与结构图同源、部件真实可见 | 后端检查与失败提示、兼容/迁移规则、单测 | 旧清单不能静默绕过；错版本被拒绝 |
| S2 | 可见 ID 提取可靠 | Blender 提取与清单格式、失败注入测试 | 细部件不漏；读取失败不写有效空集合 |
| S3 | PBR 缓存随材质着色逻辑变化失效 | 渲染器签名、原子发布/回退、缓存测试 | 新旧底图不同路径；旧图不会伪装为新图 |
| S4 | Windows 真实验收 | 同源八视图、材质对照、盲评与事实卡 | 结构/CMF 不退步，材质真实感有证据 |

## S0｜开始之前：确定唯一模型，不猜版本

1. 从最新 `main` 建立 `codex/` 修复分支，记录 commit、`git status`、Python/Blender/ComfyUI 版本、生产权重 SHA-256；不要在含未提交用户改动的目录强制覆盖。停止新批量任务或等待其完成，但不删除排队结果。
2. Windows 端只读列出 `AI渲染1` 各 `.3dm` 候选的路径、大小、SHA-256、网格数、包围盒，以及现有十机位 `pass_manifest.json` 的 `source_signature`、相机、模型版本和 CMF 方案指向。给用户看一页对照，**由用户选权威文件**。不能凭版本号最大就假定最正确。
3. 选择后在项目内留下稳定的权威模型引用及指纹；旧 rev22–28 pass、旧 PBR 和旧 CMF 方案先标记 `legacy/incompatible` 并保留，不改名冒充新图。正式重建安排在 S4，S1–S3 先用测试夹具及其他可追溯 SKU 验证。
4. 如果用户暂未选择，仍可完成 S1–S3 的代码与离线测试，但**不得声明 `AI渲染1` 已修复**，也不以它的旧图做材质 A/B。

## S1｜同源检查和旧清单处理：堵住静默绕过

**改动位置：**`web/server.py` 的 `parts_index()`、`validate_cmf_task()`、`product_base_spec()`、`_pass_manifest_issue()`；必要时扩充 `pass_manifest.json` 的模型指纹字段。参照当前 [`web/server.py`](https://github.com/hanszz1111/keyshot/blob/9e6eaa4/web/server.py#L2814)。

1. 建一个共用校验函数，例如 `validate_cmf_pass_contract(sku, view, scheme, manifest)`，供**AI 任务提交与 PBR 底图生成两条入口**调用；避免一条拒绝错图、另一条照样渲染。其输入必须是当前机位的原始清单与当前 CMF 方案，不能自动回退读取其他机位。
2. 校验顺序：①当前机位 pass/ID 图存在且格式有效；② `source_signature` 指向的源模型与方案的 `model`、内容指纹一致；③相机和尺寸与目标机位一致；④分配部件名能映射到 ID；⑤可见 ID 元数据**确实可用**；⑥当前机位有分配部件可见。不能只用 `objectid_map` 的名字存在来推断部件可见。若当前版本的清单只有文件时间/大小而无内容指纹，新增指纹并重出图，不把“文件仍存在”当同源证据。
3. **旧自动清单缺 `visible_object_ids` 时显式拒绝 CMF 任务和 PBR 底图**，提示“此结构图缺少部件可见性信息，请重建当前机位”；不要继续把 `None` 当作通过。无 CMF 分区的纯白模/普通结构图可以保留旧行为。若有人工上传结构图，只有明确提供同机位可核验的 ID 图与模型来源时才允许分区赋材；否则提示改用普通出图或重建自动 pass。
4. 分配部件**全部不可见**：阻止该机位 CMF 出图。**部分不可见**：只把可见分配写入该机位的提示/引导图；在任务事实卡记录被跳过的部件，不把它们描述为画面中的实体。背面本来不应看见的前面部件不应造成整组失败；该面若一个指派部件都不可见，给用户明确选择“这是无指定部件的机位，用主体材质出图”或修正方案，不能悄悄宣称多部位 CMF 生效。
5. 测试文件建议增加 `web/test_cmf_visibility.py`，至少覆盖：旧清单、空/损坏可见列表、方案与 pass 不同模型、相同名称但不同指纹、错机位、全不可见、部分可见、正常可见、手动图缺 ID、PBR 入口和 AI 入口结果一致。使用临时目录与合成 ID 图，不依赖私有产品数据。

**S1 出口：**在旧 `AI渲染1` 资产上必须得到明确的拒绝/重建提示；在同源测试资产上正常提交；`product_base_spec()` 和 `validate_cmf_task()` 对错源作同一判断。旧资产允许被查看，但不能误入“CMF 已生效”路径。

## S2｜可靠提取可见部件：区分空、失败和极薄部件

**改动位置：**`scripts/blender_pass.py::visible_object_ids()` 与写 `pass_manifest.json` 处。当前实现先 `list(img.pixels)` 再 `step=2` 抽样，抽样并未减少整图入内存，且可能错过只落在奇数行/列的细部件。

1. 从已导出的 16 位 `objectid.png` 提取**全像素**非零 ID（或等价的无漏检算法），按 `ID / 65535 → PNG → ×65535` 的既定编码还原，验证 ID 在 `objectid_map` 内。用较省内存的连续数组或分块读取替代 Python 浮点对象列表；记录处理耗时与峰值内存，尤其测 4096×4096 上限。仍需由 Blender/本机环境验证 PNG 读取后数值是否按预期恢复。
2. 清单建议保存 `visible_object_ids`、每个 ID 的非零像素数、编码版本和校验状态。**读取失败返回错误/无效状态，而不是 `[]`**；`[]` 只用于确实没有前景的图，而这类 pass 本身应判为失败。清理 Blender image 对象须放 `finally`，避免异常时留在会话中。
3. 防止单个噪声像素把部件误判为可见：先记录真实计数，再按经真实样张校准的最小像素阈值判“可编辑”；“出现过”与“足够大可做材质选区”分开。阈值不可随意设到会排除细按钮/边缘件。
4. 合成回归图至少含：背景 0、ID 1、超过 255 的 ID、奇数坐标上的 1 像素细线、图边缘部件、两部件遮挡、损坏 PNG、缺文件、超大 ID。并检查输出顺序稳定、颜色空间转换不改变整数 ID。

**S2 出口：**同一 ID 图重算结果一致；极薄可见部件不漏；任何读取/解码失败会阻止相关 CMF 任务并给可理解错误；4096 图的内存与耗时在 Windows 32GB 上可接受。

## S3｜给 PBR 着色器建立版本签名，避免旧图冒充新图

**改动位置：**`web/server.py::product_base_spec()`、`product_base_fresh()`、批量生成与场景报告；已有签名包含模型、CMF 方案、预设库、相机等，但**不包含 `scripts/blender_pass.py` 的实际着色逻辑**。

1. 生成 `renderer_signature`：至少纳入 `blender_pass.py` 的内容 SHA-256、CMF 预设文件 SHA-256、灯光配置/版本、必要的 Blender 大版本信息。签名同时进入 `scene_id`、每机位底图 digest 和场景报告。不要只改文件名算法却忘了关联任务的核验规则。
2. 缓存判定不止“文件存在、非空、尺寸正确”：当前请求签名须和产物记录一致。渲染过程中再次核对签名与模型/方案/相机；若变动，丢弃临时结果，不发布。先写临时文件并验证 PNG/签名，再原子发布；**旧路径与文件保留**以便回退，不就地覆盖已有底图。
3. 八视图批量以同一个 `renderer_signature` 和 `scene_id` 运行；只有当前签名的机位可记为 `cached`。若批次一半成功、一半失败，报告需明确哪些新图可用，不把混合新旧签名的八面标为完成。
4. 单测增加：仅改一行着色逻辑、只改材质纹理配置、换灯光版本、换 Blender 版本、改相机、改模型、改 CMF 指派，均应得到新路径；与旧缓存同尺寸也不得被复用；签名不变则稳定命中；渲染中配置变化不得发布。必要时加入模拟旧缓存迁移测试。

**S3 出口：**同一产品、同一机位仅因材质着色器变化也获得新底图路径；旧图可回退但不会进入新批次；`web/test_product_base.py` 的缓存/批量测试通过。

## S4｜Windows 实图验证与是否推广

1. 取得 S0 的用户确认后，从唯一 `.3dm` 重出 `AI渲染1` 十机位 pass 与 PBR（至少八个标准机位）；每个清单记录同一个模型指纹，机位相机正确、结构 pass 完整、可见 ID 非空。重建 CMF 方案时以当前 ID 高亮确认真实部件与文字标注，避免乱码网格名误选；保留旧方案快照。
2. 先做**渲染器层面**的 A/B：同一模型/相机/灯光/颜色，旧均匀材质与新微纹理各出塑料、橡胶、喷砂/拉丝金属局部及八面总览。记录纹理尺度、拉丝方向是否跨视角固定，高光是否符合工艺，是否产生伪分模线、金属过曝或脏背景。不得用 MAE 大小代表质感分数。
3. 再做**AI 层面**对照：同一 PBR 底图和种子，现有 Qwen 与局部精修实验臂；掩膜外合成后逐像素相同。外部 FLUX/Kontext 候选是另一个模型家族，作为整链对比独立记录，不写成“只改一个参数”的严格 A/B。
4. 三种不同 SKU（硬边/多部位、曲面、透明或金属）× 八机位 × 至少两个种子；两人独立盲评结构/视角、部位 CMF、工艺真实感、反光与背景。真实图留私有目录；Git 只提交脱敏事实卡、哈希、统计、失败例文字。评价表和阈值在看结果前固定，若只有单人目视则写“证据不足”。
5. **晋级顺序：**无新的孔位/分模线/部件数硬错误 → 同 SKU 八面材质与颜色一致 → 盲评质感优于或不低于基线 → 8GB 的耗时/内存可接受。否则保留旧默认，实验入口标“实验”，记录失败原因与回退版本。

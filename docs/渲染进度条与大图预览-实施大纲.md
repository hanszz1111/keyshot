# 渲染进度条与大图预览 · 实施大纲

> 状态：设计提案，尚未实现或在 Windows 实机验收。适用于千问主力链路与 SDXL 备选链路；不改变现有生成参数、任务顺序和产物。

## 1. 目标与当前缺口

- 用户提交后，能看到当前在做什么、已完成多少张、已经等待多久；有可靠数据时显示当前采样步数和预计剩余时间。
- 一批八机位、多候选的任务，应明确显示“已完成张数 / 总张数”、当前机位与候选编号；失败与被主视图依赖阻断的任务单独计数，不能冒充完成。
- 完成图的**缩略图本身可点击**，原地打开大图；保留下载和“对比白模”入口。

当前 `web/app.js` 每约 3 秒调用一次 `/api/comfy/poll`；`web/server.py` 的该接口通过 ComfyUI `/history/{prompt_id}` 判断结果，返回的是运行/完成等粗状态，没有采样步数。结果卡已有“查看大图”按钮，但它只把页面滚动到有限尺寸的顶部预览，点击缩略图不起作用。长批次仍由前端顺序执行，关闭网页后不能保证剩余任务继续运行；进度条不能被误写成“后台持续运行”的承诺。

## 2. 页面交互大纲

### 2.1 任务进度卡

位置：生成按钮下方显示当前任务进度卡；任务抽屉同步显示简版。不要重复展示两组相互矛盾的进度。

```text
正在生成 · 千问 · 候选系列 2/4 · 左前 3/4
整批：已完成 9/32 张  [██████░░░░░░░░] 28%    失败 0 · 等待 22
当前：采样 8/25 步      [████░░░░░░░░░░] 32%
已用 04:18 · 预计剩余约 12–18 分钟（估算）
```

- “整批百分比”只按**成功落盘的图片数 / 计划图片数**计算；当前张的采样进度另起一行，不混成“整批已完成”。可附“当前张约 32%”，但不得将其算作已完成图。
- 白模/深度补齐、上传参考图、排队、采样、解码保存、结果校验各显示不同阶段。无法获得阶段内部精确进度时使用不确定动画和文字，不显示编造的数字。
- 计时从用户提交任务时开始；排队时间和真正采样时间分别记录。预计剩余基于相同引擎、尺寸、步数和参考图数量的近几次成功任务耗时中位数，样本不足时只显示“计算中”；展示为区间并明确“估算”，避免 8GB 显存波动造成误导。
- 前端刷新后从后端任务记录恢复批次、已完成数、起始时间和最近状态。页面关闭期间，不能暗示前端队列仍会自动推进；若未迁移后台队列，重新打开时明确提示“继续运行剩余任务”。
- 出错、离线、超时、用户取消时停止计时动画并显示原因及“重试本张/检查服务”；断线重连时保留已完成计数，不倒退。

### 2.2 点图看大图

- 将已完成结果的缩略图包在语义化按钮中，点击打开遮罩式大图查看器；“查看大图”文字按钮可暂时保留以便发现功能，两者执行同一动作。
- 大图初始按屏幕自适应完整显示；提供放大/缩小、重置、关闭、下载。放大后可拖动。桌面支持 `Esc` 关闭、左右方向键切换同一候选系列的相邻机位；按钮有可见焦点，关闭时焦点返回原缩略图。
- 顶部显示产品编号、候选系列、机位、尺寸和模型；切换机位时保持同一候选系列，不把不同候选的材质/颜色误认为同一产品。图片模式单张结果按时间顺序浏览。
- 大图打开后才加载原图；列表继续使用懒加载缩略图，避免 200 张长批次同时解码占满浏览器内存。加载失败显示“图片暂不可用”和重试，不跳到别的图；不对原图二次放大或重编码。
- “对比白模”和“下载图片”仍是独立按钮，不因点击卡片或冒泡而意外触发；手机端保留明显关闭按钮，图片不超出可视区域。

## 3. 数据与接口方案

### P0：先交付可靠的基础进度与大图

1. 后端给任务返回统一字段：`task_id`、`batch_id`、`engine_id`、`view`、`variant`、`status`、`phase`、`submitted_at`、`started_at`、`finished_at`、`error`、`output_ready`。现有任务状态继续兼容旧页面。
2. 前端在现有轮询基础上计算“已完成 / 总数”、阶段和已用时间。`output_ready` 只在结果文件成功下载、写入并能读取后为真；在此之前绝不显示 100% 或“已完成”。
3. 实现缩略图点开大图弹层、键盘操作、原图延迟加载和异常状态。优先复用已有 `outputUrl()`、结果卡分组及任务 ID，不复制一份新的结果列表。

### P1：真实采样步数

1. 后端分别连接 SDXL 和千问所用的 ComfyUI 实例，订阅 `/ws?clientId=...`。提交 prompt 时传对应 `client_id`，以 `prompt_id + engine_id` 关联任务；只接收当前任务的事件，防止双实例或其他 ComfyUI 客户端串进度。
2. 解析 ComfyUI 的 `progress`（`value/max`）及适用版本的 `progress_state`、`executing`、`execution_error` 等事件，归一为任务级阶段和采样进度。节点进度并不等同整张图或整批进度；只对已识别的采样节点标注“采样 x/y 步”。不同 ComfyUI 版本与工作流先做兼容测试。
3. 浏览器只连接本项目后端的进度流（建议 SSE）；不要直接连接 8188/8190。若实时通道中断，降级为现有 `/history/{prompt_id}` 轮询，显示“正在生成，详细步数暂不可用”，避免进度停在假 99%。
4. 将最新阶段、步数、更新时间和任务映射写入后端可恢复状态；重启后可根据任务表和 ComfyUI history/queue 重建最终状态。重复事件不得导致百分比倒退或重复完成。

### P2：时间估算与批次体验

- 按引擎、尺寸、质量步数、参考图数量分桶统计最近成功耗时；至少积累数个样本后给出范围，等待排队和白模补齐另算。切换配置、服务重启或失败率升高时隐藏旧估算。
- 八面图的主视图先行依赖、候选系列数、结构图补齐都要进入批次状态模型；“主视图失败→同系列后续机位阻断”显示为阻断而非完成。
- 若将来迁入后端持久队列，再提供真正的关闭页面后继续运行、暂停、取消和断点恢复；本大纲不把这项作为 P0 已有能力。

## 5. 验收清单

- **准确性**：两引擎均能正确匹配任务；`8 机位 × 多候选` 已完成计数与实际文件一致；采样事件丢失时不显示虚构百分比；文件没落盘不显示完成。
- **故障**：ComfyUI 离线/重启、网页刷新、重复或乱序事件、主视图失败、取图失败时状态与操作提示正确，进度不跨任务串线。
- **性能**：用 200 条结果模拟长列表，打开/关闭/切换大图不持续增长内存；缩略图未主动加载全部原图。
- **操作**：鼠标点击图可放大，`Esc` 可关、方向键切换限定在同系列；键盘能触达关闭、下载、对比按钮；手机屏幕不裁掉关闭按钮。
- **Windows 实测**：先用 4060 Ti 8GB 跑千问和 SDXL 各一张，再跑前面/侧面及一组完整八面候选；记录步数事件是否真实到达、计时偏差、失败恢复和截图。未完成此项前只能标“代码待实机验收”。

### 需要停止沿用的旧结论

1. [更正记录](更正记录-PIL位深误导导致的两处错误结论-20261010.md)已撤回“32 个 `.3dm` 是不同模型版本”“4 个 CMF 部件全部不可见”“大多数变化在背景”。32 个文件的内容哈希相同，4 个部件都可见。历史报告保留原始过程，但当前任务不得把撤回项当阻断。
2. 不同视角的变亮比例（0%～33.6%）是**变化量证据**，不能单独证明材料不一致。要按同一部件、可见面积、光照和目标材质比较。
3. Windows 实验曾测得 CPU KV cache 约 40% 提速，生产工作流没有该节点。新规划把它列为复测后可选项。
4. [文档索引](README.md)之前对同一 Qwen 文档分别标“P0–P3 已执行”和“待执行”，也把已实现的进度/大图能力写成“尚未实现”。本次按代码与测试证据统一描述。

## 二、产品发展目标

形成一条可复现的“原模型 → 八机位结构与真材质底图 → 千问 INT8 有限度润色 → 部件/几何检查 → 人工挑选”流程。用户能快速为一个产品选材、布光、生成系列图，并清楚知道哪些细节来自模型、哪些经过 AI 修改。重点衡量材料和工艺真实感、结构保真、八面同物与一次任务完成率；清晰度增加和步数提升不单列为质量目标。

## 三、实施顺序与通过条件

| 阶段 | 工作内容 | 可交付与通过条件 |
|---|---|---|
| P0 文档与事实基线 | 固定代码/工作流/权重哈希，更新当前事实入口；把 Windows 私有实图的证据索引写入 `AI/RESULT`。修自检警告原因，留一套非敏感合成夹具。 | 操作入口只指向当前说明；旧报告的撤回项不会误导下一轮；自检无误导性“通过但清理失败”。 |
| P1 几何与部位 | 用 STEP、3DM、网格三类样本检查单位、朝向、居中、八机位、白模/深度/法线/ID。对 16 位 ID 用已知值夹具比对完整解码；给所有可见部件统计占比和“可编辑/太小”状态。 | 八面结构图均可打开且相机正确；部件点击、颜色和材质标签与实际 ID 一致；失败指明具体机位/原因。 |
| P2 材质与灯光 | 按[保留 INT8 方案](保留千问INT8-工业材质与八视角优化方案-20261010.md)落六个可靠材料、外部 PBR 包、物理尺度和三档灯光；把着色器、材料文件及灯光内容哈希放进场景签名。 | 同一部件跨八面纹理和颜色归属稳定；修改材料会生成新底图；旧结果可回看，不能混入新系列。 |
| P3 千问有限度增强 | 保持 INT8 基线，分别对照真实 PBR 底图、提示词和第二参考。需要局部处理时实现实际的选区裁切、合成与边缘保护，再开放对应开关。 | 与 P2 真材质底图配对比较，无新增孔位/轮廓/文字硬错误，目标材料质感提升；选区外逐像素不变。 |
| P4 八面系列验收与交互 | 一次任务冻结模型、材料、灯光、相机和提示词版本；展示真实任务进度、耗时及大图并排对照；失败可从同一签名继续。 | 八面图片、参数卡和来源完整关联；无串产品/串机位/串材质；状态和剩余时间在 Windows 长任务中可理解。 |
| P5 性能及候选技术 | 单独复测 CPU cache 和可选材质生成工具；记录峰值显存、时间和视觉回退。 | 在 4060 Ti 8GB 上可回退，真实耗时/显存优于基线且质量无回退才启用。 |

P0–P2 是先决条件。P3 可以做小范围对照，但在结构/材质输入未稳定前不升级成默认工作流。P5 不改变用户已经选择的 INT8 主模型。

## 四、实测与发布门槛

1. 准备至少 3 个不同结构的产品：一件塑料+橡胶、一件金属高反射、一件零件多/开口复杂。每件固定权威模型哈希、材料方案、八机位和参考图。
2. 首轮 3 产品 × 3 机位 × 2 种子 × 2 方案 = 36 张；保留全部失败图、耗时和显存。候选方案有收益后扩至 3 产品 × 8 机位 × 2 种子 × 2 方案 = 96 张。比较输入、提示词和第二参考时各开一轮，不能混改。
3. 检查项：孔位、轮廓、接缝、标识、部件材质归属、纹理尺度与方向、反光层次、接触阴影、八面同物。结构硬错误逐张记录；材料质感与立体感由两人盲评 0–2 分。MAE、变亮面积仅用于定位变化，不能充当画质分。
4. 准入：结构硬错误不增加、八面 CMF 不下降、材料质感与立体感平均评分提高，且 Windows 8GB 环境没有不可接受的失败率/耗时。结果和主观评分未回填前统一标“证据不足”。

## 五、文档治理与双机交接

- `README.md`、`docs/README.md`、`docs/功能与限制.md` 只写当前入口与能力状态；根[过程文档](../00-AI白模渲染器-过程文档.md)逐次登记变更；技术细节留在专项报告，旧报告保留更正链接。
- `AI/MASTER_CONTEXT.md`、`AI/README.md` 的早期架构或轮次描述可能落后于当前代码。Windows 发起新轮时，在 `AI/TASK.md` 写明准确 `base_commit`、使用的模型哈希和证据；执行结果在 `AI/RESULT.md`，Mac 独立复审在 `AI/REVIEW.md`。不要直接把历史 R3/R4 改写成新轮成果。
- 每阶段回填：代码提交、变更文件、测试环境、输入/输出摘要、成功/失败数、关键反例、结论状态和回退方法。上传公开仓库时只放脱敏文字与合成样本，不放客户模型、真实输出、数据库或权重。

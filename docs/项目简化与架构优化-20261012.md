# 项目简化与架构优化记录（2026-10-12）

## 审核结论

这次检查的是公开仓库的代码、页面和文档，不含 Windows 私有模型、图片、ComfyUI 与 Blender 运行环境。现有功能可继续使用，但复杂度集中在两个单文件：`web/server.py` 约 4500 行，混合资产、数据库、工作流、任务、模型转换和 HTTP 路由；`web/app.js` 约 2400 行，混合状态、3D 交互、CMF、出图和项目管理。大改架构前必须先建立接口与用户操作回归，不能一次性重写。

| 发现 | 本轮处理 | 后续边界 |
|---|---|---|
| 文档索引逐篇解释历史方案，读者容易把待执行误看成已上线 | `docs/README.md` 改为按使用目的导航，保留原方案和证据文件 | 历史文档不删除；后续按证据状态标注，不再复制同一结论到多个首页 |
| 首屏把常用操作与参考图、实验底图、种子、结构图工具并排堆叠 | 收进有名称的原生折叠区；核心的产品、主体材质、机位、张数、尺寸、质量和生成按钮不隐藏 | 用 Windows 浏览器实测键盘、窄屏、真实八面任务；不要只凭静态页面判定可用 |
| 任务载荷 JSON 在界面多处重复解析，且容错行为不同 | 统一成 `taskPayload()`，供模式、系列、结果卡和执行前检查复用 | 未来给任务载荷加版本号与 schema 测试，不直接改变历史任务格式 |
| 旧版 HTML 与当前首页并存 | 当前仍只运行 `web/index.html`；旧文件保持历史对照，不进入启动路径 | 确认旧版不被外部文档引用后再移入归档，不在本轮删除 |
| 多个方案文档重复承诺“改善质感/八面一致” | 首页改用当前复审记录作为事实入口 | 不把方案、单机成功或像素变化写成画质验收通过 |

## 推荐的下一轮拆分顺序

1. **先锁契约**：为资产清单、CMF 方案、任务载荷、场景签名和结果元数据建立版本化样例；补 HTTP 回归（成功、缺图、旧缓存、失败重试、历史任务）。
2. **后端按职责提取**：先抽纯函数与文件操作（路径/签名/校验），再抽 Blender/ComfyUI 适配器，最后抽 HTTP 路由。保持现有 URL 和 JSON 形状，逐块迁移；每块过自检和 Windows 真实素材回归后再继续。
3. **前端按工作流提取**：先拆不依赖 DOM 的任务/视角/质量规则，再拆 CMF 与 3D 预览；状态仍由一个顶层模块协调，避免引入第二套状态。除非构建需求明确，暂不新增大型前端框架。
4. **把长批次移到后端**：目前网页顺序调度，关闭页面不能保证剩余任务继续。先设计持久任务状态、取消、重试与恢复，再改进度条；不可将当前任务级百分比宣传为单张采样级实时进度。
5. **Windows 验收**：同一真实模型做前、后、顶、底、左右 3/4 八视角；记录模型哈希、CMF 版本、Blender/ComfyUI 版本、失败日志、时间与显存。视觉质感用盲评和逐部件材料核对，不以“测试通过”代替成图质量结论。

## 本轮验收边界

本轮只做低风险入口收敛、界面渐进披露和一处重复代码统一；没有删历史记录、改变渲染算法、引入新依赖或宣称八面画质问题已解决。前一次分支的 CMF 校验/底图缓存修复已一并带入本分支，仍待 Windows 真实模型复验。

离线验证：`web/selftest.py` 93/93；产品底图、CMF、16 位部件号和新页面结构测试合计 32/32；前端提示词 12/12、进度时间 11/11；`web/app.js` 语法与差异格式检查通过。页面结构测试检查 ID 唯一、关键控件存在与折叠区标签平衡。真实浏览器视觉、Windows 8GB 出图和跨视角画质未在本机验证。

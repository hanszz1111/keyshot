# 项目管理与维护标准

## 目录职责

| 路径 | 内容 | 管理规则 |
|---|---|---|
| `web/` | 唯一运行网页、HTTP 服务、相关离线测试 | 不存旧版网页；接口变更附回归证据 |
| `scripts/` | 渲染、启动、检查和实验工具 | 日常入口从根目录批处理调用；实验脚本不自动加入生产流程 |
| `config/` | 工作流和预设 | 不提交任务库、密钥或机器专属配置 |
| `docs/` | 安装、使用、专题设计、当前实测 | 入口只维护 `docs/README.md`；历史结论注明版本 |
| `docs/archive/` | 旧网页、旧方案、历史报告 | 保留追溯，不当作当前操作说明 |
| `AI/` | 双电脑任务与复审 | 使用 MASTER_CONTEXT → DECISIONS → TASK → RESULT → REVIEW |
| `.github/` | 自动检查、问题和合并说明模板 | 每次推送、PR 执行离线检查 |
| `assets/`、`outputs/` | 本机产品资产与渲染结果 | 不进入公开 Git |

## 日常维护流程

1. 从约定基线建立分支，先检查另一台电脑的未合并任务。
2. 修改代码或配置，同时更新相关用户指南和过程文档的一条记录。
3. 用 `python scripts/check_project.py` 运行统一离线检查；Windows 真实出图另外留证。
4. PR 写清触发条件、改后行为、验证和剩余问题。通过审核后合并，旧分支再按团队约定清理。
5. 历史文件需要归档时使用 Git 移动，并更新当前入口链接；历史报告原文保留，不重写当时观察。

## 成熟度检查与剩余工作

| 维度 | 当前状态 | 下一步验收条件 |
|---|---|---|
| 唯一运行入口与历史归档 | 已整理 | 新增页面不得另建一套生产入口 |
| 自动回归 | 已提供跨 Windows/Linux CI 与统一命令 | GitHub 实际运行通过；本机成功不等于云端已成功 |
| 网站信息准确性 | 已修离线模型误报、保形承诺和未经标定的 IoU 通过判定 | 真实素材检查 UI、结构、材质和进度 |
| 任务持久化 | 数据已落库，批次仍由网页调度 | 关闭网页、重启服务后批次继续且不重复提交 |
| 模块边界 | 前后端仍有大型单文件 | 按[架构优化顺序](项目简化与架构优化-20261012.md)拆分，每次保持接口兼容 |
| 画质验收 | 仍缺系统跨 SKU 盲评 | 固定模型/机位/材质/种子，保留失败例和人工评分 |
| 发布管理 | 尚无正式发布验收包 | Windows 安装、升级、回退、真实出图通过后再标稳定版本 |

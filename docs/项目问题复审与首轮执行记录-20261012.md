“代码证实”表示可从当前仓库直接核对；“Windows 报告”表示有入仓文字但原始产品资产不公开；“推断过强”表示数字本身不足以支持报告中的因果或画质结论。

## 二、按校正后的大纲执行了什么

1. **可追溯缓存（P-03）**：`web/server.py::product_renderer_signature()` 读取 Blender 渲染脚本和 CMF 预设文件 SHA-256，连同固定渲染配置进入场景签名和报告。哈希变化后新底图使用新路径，历史图不会作为新版本命中。已接入的临时输出校验、原子发布保留。未来真正接入用户贴图/HDRI 时，须把这些文件内容哈希加入同一签名；本轮未声称锁定 Blender 安装版本。
2. **同源可见性（P-04）**：有部位指派时 `product_base_spec()` 调用现成的 `validate_cmf_pass_contract()`。旧清单、模型内容不符、机位错误、ID 图缺失/读取失败、目标部件当前面不可见会拒绝，错误会在底图入口显式返回。仅主体材质不需要部位 ID，保持原能力。
3. **交叉验证可复现**：`scripts/_crosscheck_ids.py` 现在真正执行 A/B 双解码并逐 ID 比像素数，失败立即报错；将 `objectid_mask.py` 的 Pillow 导入移到“导出掩膜”分支，让 Blender 内 Python 在只有 numpy 的环境可读 ID。
4. **大部件定位（P-09）**：新增当前机位 `cmf_coverage()` 与网页清单，按可见像素排序显示前 20 个未显式指派部件，点击定位到 3D 模型；显示面积占比并说明余下区域使用主体材质。批量材质应用复用原界面，不替用户决定材料。
5. **文档纠偏**：更新问题台账及 P0–P1 记录中的因果边界、测试依赖、已完成状态；源代码里撤回“AI渲染1 指派部件全不可见”的过时注释。历史原始报告不删除。

本机验证：`web/test_product_base.py` **19/19**；`web/selftest.py` **93/93**；使用本机捆绑的含 numpy/Pillow 的 Python 跑 `web/test_objectid_precision.py` **7/7**；前端语法、Python 语法与 `git diff --check` 通过。P-09 的真实 3D 定位和交叉验证增强脚本尚待 Windows Blender 真实产品复跑。
